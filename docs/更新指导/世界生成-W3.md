# 世界生成 · W3 —— 气候与柯本（S3 + S4）

> 状态：⬜ 未开始（用户将统一审阅）
> 依赖：W2
> 总纲：[世界生成-过程模拟.md](./世界生成-过程模拟.md)（第五节 S3 / S4、第四节 4.2 分层分辨率）

## 一、目标

算出**12 个月的气温与降水**，据此得到**柯本气候分类**与**生物群系** ——
让地图上出现**雨影沙漠、季风、极地/雪线**这类"一眼就觉得对"的地理。

## 二、做什么

### 2.1 S3 气候（**在 128×128 的粗网格上算**，见总纲 4.2）

| 量 | 怎么算 |
| --- | --- |
| **气温** | 纬度带（把死地图的 y 映射成纬度）+ **季节相位**（12 个月）+ **海拔递减**（越高越冷）+（可选）海陆热容差 |
| **降水** | **风带**（0~30° 信风 / 30~60° 西风 / 60~90° 极地东风）+ **海洋水汽源**（从海面出发）+ **迎风坡抬升**（水汽沿风向累积 → 遇山抬升 → 多雨）+ **背风坡递减**（雨影） |

> ⚠️ 顺序依赖：**必须先有高程与水域**（才知道水汽从哪来、山在哪），所以这一步吃 W2 的结果。

### 2.2 S4 柯本 + 生物群系

- 用**月均温 + 月降水**套柯本判据（Af/Am/Aw/BW/BS/Cs/Cf/Df/ET/EF…）。
- **生物群系 = 柯本 + 高程**（高山、雪线）。
- 把 biome **上采样**到 512，供 W5 的采样转换用。
- 输出**正好喂给现有的两层**：`terrain`（地貌）+ `cover`（地物）→ 这是 v1.8.21 就留好的口子。

## 三、验收

1. **人看**：地图上能看到
   - **山脉背风侧是干旱区**（雨影沙漠）；
   - **低纬多雨、极地严寒**；
   - 森林/草原/沙漠/雪原**成带分布**（不是随机撒点）。
2. **同种子两次生成逐位一致**。
3. 4 个无头自检全绿。

## 四、范围外

- **不做洋流**（可留接口，将来再加；它影响不大但成本不小）。
- **不做"真实地球经纬度"**：这是一块**平面区域**，纬度是"映射出来的"，不是真球面（总纲第十一节）。

## 五、风险

- 12 个月 × 128×128 = **约 20 万个"格·月"**，是**本项目最大的一笔算力开销**。
  要在 W3 里**实测生成耗时**并定默认质量档（总纲第十节把它列为"必须实测的数"）。
- 柯本判据的**阈值细节**属可逆参数（助理按国际标准实现，再按观感微调）。

## 六、具体实现设计（2026-10-13 准备，等用户点头后开工）

### ⚠️ 先说一件架构上的事：**W3 必须提前引入"参数图"**

- **温度可以按格算**（纬度 + 高程），但**降水不行**。
  降水本质是"**风把水汽从海上吹进来、沿途一路下雨、被山挡住就下在迎风坡**"——
  它必须**按一整张场来推**（沿着风向一格一格累积水汽），**逐格纯函数做不到**。
- 所以 W3 会**提前用上 W5 的"参数图"骨架**：一张 **128×128 的方格参数场** + 采样成地块。
  **这不是走错顺序**：W5 做的是"**裁切**"，参数图本身早一点建起来是自然顺序
  （总纲的三段式架构本来就要求"先生成死地图 → 再裁成六边形"）。
- 参数图**不进存档**（由种子 + 配方即可重算）→ 所以 **`SAVE_VERSION` 不用再升**
  （W1 已经升到 5，老档照旧删）。

### 分三步做，每步都能单独验、单独提交

| 子段 | 做什么 | 验收（尽量做成断言） |
| --- | --- | --- |
| **W3a 参数图骨架 + 温度** | ① 128×128 方格参数图（按地图外接矩形铺），**按种子缓存**；② 双线性采样；③ **温度场**：纬度梯度（用轴向 r 模拟）× **12 个月** + 海拔递减；④ `moisture_of()` **暂时仍用旧噪声** → **观感基本不变**（可以拿截图对照） | 同种子逐位一致；**极地冷 / 赤道热**；同纬度下**海拔越高越冷** |
| **W3b 降水（风带 + 雨影）** | ① 12 个月风带（按纬度带：信风 / 西风 / 极地东风）；② 从海上出发**沿风推水汽**（经过陆地逐渐减少、按温度定"能含多少水"）；③ **迎风坡抬升 → 下更多雨**；④ 背风侧 → **雨影沙漠** | ★ **雨影断言**：同一座山，**背风侧平均降水 < 迎风侧**（这条把"雨影"变成可测的） |
| **W3c 柯本 → 生物群系** | 按柯本标准用"温度 + 降水"分类（Af/Am/Aw/BW/BS/Cs/Cf/Df/ET…），再把**类别**映射回现有的 **terrain / cover 两层** | 类别数 ≥ N；**沙漠出现在雨影与副热带**；**苔原只在极地**；地物（草原/森林/沼泽）跟着气候走 |

### 与现有代码的接缝（改哪里，尽量少动）

- `world_gen.moisture_of(c, seed)` → 改成**从参数图采样**（**签名不变**，调用方一行都不用改）。
- `world_gen.biome_of(e, m)` → 做柯本还需要**温度** → 扩成 `biome_of(e, m, t)`
  （调用点只有两处：`_make_tile()` 与自检）。
- 参数图的构建与缓存写在 `world_gen` 里，照 `_eroded` / `_crust` 那套**按种子缓存**的写法。

### 必须实测的数（总纲第十节点名）

- **生成耗时**：12 个月 × 128×128 ≈ **20 万个"格·月"**，是本项目最大的一笔算力开销。
  → **实测一遍**，再定默认质量档（例如 128 还是降到 96）。
- 若耗时过高，降级顺序（都是可逆参数）：月份抽样（12 → 4 个代表月）→ 网格 128 → 96 → 64。

## 进度：W3a 已完成（2026-10-13）

### 做了什么

- 新增 `scripts/core/climate.gd`（`class_name Climate`）：**128×128 气候参数图** + 双线性采样。
  温度 = **纬度梯度**（用像素 y 模拟，南北反相）× **12 个月** + **海拔递减**。
  - 用 `Callable` 把"按格取高度"传进去 → **避免 Climate ↔ WorldGen 互相引用**（GDScript 里那很难看）。
  - `temp_at_pixel()` / `temp_at()` / `annual_temp_at()` / `month_range()`（柯本要用的最冷月/最热月先备好）。
- `world_gen`：新增 `climate_for()` / `annual_temp_at()`；`biome_of(e, m)` → **`biome_of(e, m, t)`**。
  - **W3a 只加了一层**：`_moist_for_cover()` 把"可用湿度"按温度打折（≥5℃ 不打折、≤-5℃ 全打光）
    → **原来的判断一字未改**；完整柯本在 W3c。
  - 接线点：`_make_tile()`（把温度真的喂进去）→ **不是"接了一半的架子"**。
- 新增自检 `tests/climate_check`（**第 6 个无头自检**）。

### 实测

| 指标 | 数值 |
| --- | --- |
| **建场耗时** | **1459 ms**（128×128×12 = **196,608 个格·月**）；第二次取 = **0 ms**（命中缓存） |
| 年均温范围 | **-25.8 ~ 27.6℃** |
| 赤道带（\|纬度\|≤0.15） | 均 **18.1℃** |
| 极地带（\|纬度\|≥0.75） | 均 **-16.4℃**（差 **34.5℃**） |
| 同纬度海拔效应 | 最高格 7.6℃ < 最低格 14.5℃ ✓ |
| 极冷格（<-5℃）森林数 | **0**（对照：不加温度时这些格本来有 **40** 个森林）→ 温度确实起作用了 |

### 自检抓到的两个错（都是我的）

1. **海拔递减写错了**：原来用 `e × 3000 米` → **海岸线（e=0.36）就等于 1080 米高**，
   整张陆地被冻住（赤道带年均温只有 8.7℃）。改成**以水线为海平面**：`(e-0.36)/(1-0.36)`。
2. **测试自己写错了**：用"半径 r ≥ 18"当极地 —— 但**地图是圆盘**，横向远处的格子 y≈0（属热带），
   于是"极地带"混进了热带格子。**纬度必须看像素 y**，改成按 \|纬度\| 分桶后，温差从 13.5℃ 变成 34.5℃。
   另外"相邻格温差 < 6℃"这条也不合理（**山顶紧挨大海**本来就该有十几度落差）→
   改成测**采样器本身连续性**（沿像素空间密集取样），并新增 `temp_at_pixel()` 入口
   —— **这个入口 W3b 的降水沿风向行走正好要用**。

## 进度：W3c 已完成（2026-10-13）→ **W3 整段收工**

### 做了什么

- `climate.gd` 新增 **降水毫米标尺 + 柯本分类**（柯本要的是**绝对量**，不是归一化湿度）：
  - `PRECIP_MM_PER_RAW`：把场里的原始降水换算成 **毫米/年**（标定：raw 85 分位 ≈ 0.003 → ~1600mm）。
    ⚠️ 这是**近似标尺**（不是真实物理量），只为让柯本阈值有意义；可逆。
  - `annual_precip_mm()` / `driest_month_mm()` / **`koppen_at()`**：
    判据顺序照柯本原意 —— **最热月**（够不够暖 → E）→ **干湿**（够不够湿 → B）→ **最冷月**（A/C/D），
    再按干湿给子字母（f/s/w）。简化过，够本作用。
- `world_gen.biome_of(e, m, koppen)`：**W3a 那个"拍温度阈值"的做法被取代** —— 现在
  「极地不长树」「沙漠不长树」「草原只长草」都是**气候类别**说了算（`_moist_for_climate`）。
  **高度那一层判断一字未改**（水/平原/丘陵/荒地/山）。
  - E（极地）**单独处理**：地面是**荒地**而不是沙漠（沙漠是 B 类的事）。
  - BW（沙漠）→ 可用湿度清零 → 低地自然成为 **dune**；BS（草原）→ 至少长草、但不到森林。

## W3c 收尾修正（2026-10-13，用户指出"草原必须看得见"）

用户看过后说：**降水不必那么严谨**（"这不是个以硬核为主的游戏"），但**草原是肯定要有的**。
于是回头查"草原为什么少"，发现问题比他说的还基础：

```
修正前：地物 { "":881, forest:269, swamp:120, grass:117 }     ← 草只有 8%
        地形 { water:603, plain:373, hill:236, mountain:107, wasteland:68, dune:0 }
```

**根因**：原表的湿度分档**把"草地"放在比"森林"更湿的一档**（`m>0.45→草`、`m>0.22→林`），
草原因此被挤成一条窄带；而"沙"还要求低地，干旱区多半落在丘陵上成了秃地。

**改法（按常识顺序重排）**：**干旱→沙 ／ 中湿→草原 ／ 较湿→森林 ／ 最湿→沼泽**：

| 档 | 新的地物 |
| --- | --- |
| `m > 0.75` | 沼泽 swamp |
| `m > 0.50` | 森林 forest |
| `m > 0.22` | **草原 grass**（丘陵带同样适用） |
| 更低 | 低地 → **沙 dune**；高地 → 秃地 |

另两处：① **BW（沙漠）在低地一律显示成"沙"**（`e < 0.62`）——
否则沙漠会变成"秃丘陵"，玩家根本看不出那是沙漠；② 柯本的**沙漠/草原分界从阈值的一半放宽到 0.35**，
让"沙漠→草原→森林"的过渡真的出现。

**实测**：草地 **117 → 171 格（占陆地 22%）**；森林 269 → 230；沼泽 120 → 105。
6 个无头自检全绿。

### ⚠️ 仍未解决 / 未验

- **柯本 BS（草原）标签仍是 0 格**：中等降水的格子恰好都落在寒冷区，先被判成 ET（苔原）。
  **这个标签玩家看不见**，不影响画面；要让标签也出现，得动 B 类判据与温度顺序，暂不做。
- **"BW→沙"那条改动在该种子的分布上看不到 dune**：说明**那个种子的沙漠都在高海拔**
  （干旱=离海远=内陆高地），所以显示成秃地/山而不是沙。
  → **需要在别的种子上确认"沙"真的会出现**（下一步顺手验）。

三步（W3a 参数图+温度 / W3b 降水+雨影 / W3c 柯本+生物群系）全部落地，
**参数图（128×128）与柯本分类都在，W5 的裁切可以直接接上**。

## 进度：W3b 已完成（2026-10-13 深夜）

### 做了什么

**降水是"推出来的"，不是画上去的**（`climate.gd` 的 W3b 段）：
沿**风向逐行推进水汽** —— 海上补充 → 经过陆地就下掉一些 → **爬坡（迎风坡）下得更多** →
翻过山脊水汽已经没了 → **背风侧干旱（雨影）**。

- 风向按纬度带（`wind_at`）：信风（由东向西）／西风（由西向东）／极地东风。
- 冷空气含水少：温度低到一定程度后降雨能力线性掉到 0。
- ⚠️ **只做东西向推进**（风带本身带南北倾斜，但推进时忽略）→ 代价是
  **只有南北走向的山**才有明显雨影，东西走向的山不分迎背风。够 W3b 用。
- `world_gen.moisture_of()` **不再是一张噪声**：改成取气候场的**年均降水**（归一化 0~1）。
  归一化参考**按场自动定**（年均降水的 85 分位），不再手调常数。

### 实测

| 指标 | 数值 |
| --- | --- |
| 建场耗时 | **1506 ms**（W3a 是 1459 ms，降水推进只多花一点点） |
| 年均降水（归一化） | 0.000 ~ 1.000，均值 **0.319** |
| ★ **雨影** | 高地格 204 个：**迎风侧更湿 110 个** / 背风侧更湿 86 个 → 断言过 |
| 极冷格森林 | **0** 个（温度门仍有效） |
| 正面对照 | 暖（>10℃）且潮（降水>0.5）的丘陵里有 **125 个森林** → 查表链是活的 |

### 自检抓到的错（还是我的）

1. **每格降雨给太大**（`RAIN_ORO=3.0`）→ 空气出海岸十几格就把水汽下光 →
   **全图年均降水只有 0.015**（几乎全旱）。调小到 `RAIN_BASE=0.008 / RAIN_ORO=0.35` 后空气能吹进内陆。
2. **归一化参考手调 0.28 是错的** → 改成**按场自动取 85 分位**。
   ⚠️ 现在这个分位**碰到了下限 0.005**（说明绝对降雨量仍偏小）→ 记在此处，W3c 定"毫米"标尺时一起校准。

### ⚠️ 已知不足（留给 W3c 或以后）

- **雨影的优势幅度偏薄**（110 : 86）。想让"雨影沙漠"更抢眼，应当**加大 `RAIN_ORO`**
  （把水汽更狠地榨在迎风坡），但那会同时让内陆更干 → 要跟"归一化参考"一起调。
- 只做东西向推进 → 只有南北走向的山有雨影。
- 降水量的**绝对标尺**（毫米）还没定 —— 柯本要用，W3c 一起做。
