# 世界生成 · W4 —— 河流（S5）

> 状态：⬜ 未开始（用户将统一审阅）
> 依赖：W3
> 总纲：[世界生成-过程模拟.md](./世界生成-过程模拟.md)（第五节 S5、第六节全节）

## 一、目标

**把 1.8.21 欠的那笔账还掉**：让**连续水系真正成型**（上一次只能得到"一排排平行细流"，
根因是没有全局流向模型 —— 见总纲第一节）。

## 二、做什么

### 2.1 S5 在死地图上算水系（全局，512 网格）

| 步 | 内容 | 要点 |
| --- | --- | --- |
| 1 | **填洼**（priority-flood） | 噪声面上到处是小坑，水一进坑就断 —— 不填洼，汇流量永远攒不起来 |
| 2 | **流向**（D8 或 D∞） | 平地也要定出流向（高度相同则比坐标键，保证确定、不打转） |
| 3 | **汇流累积** | 得到每格的**流量** —— 这就是"河的大小" |
| 4 | **切谷**（按 `world_age` 调轮次） | 流量大的地方把高程削下去 → 河谷。**"世界多老"就是"侵蚀跑几轮"**（总纲 3.6） |
| 5 | 输出 | `flow_accum` / `river_mask` / `lake_mask` |

> ⚠️ **海洋必须当"出口"**（最低边界条件），否则水会在图边缘堆着、形成假湖。

### 2.2 转换成地块的**边**（用户 2026-10-13 定的规则）

| 规则 | 内容 |
| --- | --- |
| 表示 | 河流记在**边**上（`state["edges"]`，W1 已建好）；**1~2 条边 = 过境**；**六条边全是同一类**才有特殊含义 |
| 两类边 | `river_edge`（河道）／ `water_edge`（水陆分界）——**湖中岛 = 六边全 water_edge**；**六边全 river_edge = 自循环（异常）** |
| **短河判据** | **`保留 = 流量 ≥ 阈值 或 终点是海/湖`**（用**流量**而不是长度 —— 入海口那一段很短但流量最大） |
| **长河起点** | 高程局部偏高 + 不是水域 + **汇水面积刚越过阈值**（分水岭附近那一滴） |
| **终点** | 海 / 湖 **或** 内陆洼地（**允许内流河** —— 对雨影沙漠特别有味道，总纲 6.2 第 4 条） |
| 画线 | 按死地图轨迹**采样成地块序列**（沿流向走，每进入新格记一次），把**相邻两格之间的边**标为 `river_edge` |

### 2.3 三个最容易出 bug 的点（总纲 6.3）

1. **跳格必须补路** ⚠️：采样序列里若出现**两个不相邻的地块**，沿最短路径补中间格 —— **否则河会断线**。
2. **树状分叉**：真实河流是树（有支流）。按"从河口上溯到每一条源头"各画一条链，**共享下游段去重**。
3. **自循环校验**：六边全 `river_edge` = 异常。**只在开发期看一眼**（用户已定：不加自检断言）。

### 2.4 渲染

- `hex_map_view` 从"整格 `draw_polyline`"改成**逐边 `draw_line(corner[k], corner[k+1])`**；
- **粗细按流量分级**（溪 / 河 / 干流）；
- ⚠️ 粗河在顶点会有小缺口 → **顶点补一个小圆点**或略作延长；
- ⚠️ 河道 / 水陆分界 / 领地边 / 悬停高亮 **四套描边会互相竞争** → 定优先级与配色。

## 三、验收

1. **人看**：水系**连成树**（支流汇入干流、最终入海或入湖），**不再是平行细流**。
2. **河流密度**要能调到一个"像地图上的水系"而不是"一堆蓝线"的程度（总纲第十节：必须实测）。
3. **同种子两次生成逐位一致**；4 个无头自检全绿。
4. 湖泊/海洋与"湖中岛"在图上**语义清楚**（六边全 water_edge 的格子看得出来是被水围住的）。

## 四、范围外

- **不做水的动态**（水位涨落、季节洪水）——先静态。
- **不做运河**（那是"宏伟行政工程"，属玩法，另开）。
- **不动美术**（仍用描边表现）。

## 五、风险

- **这一段是本项目"最像上一次翻车"的地方**（上一次就是河流卡住）。
  差别在于：这次是**全局流向模型**（填洼 + 流向 + 汇流），不是"在噪声面上凑"。
  如果还不对，**先查"海洋是否被当成出口"和"填洼是否真的填平了"**这两件事。

## 进度（2026-10-13）：**河道落到"边"上**（W4 本体第一步）

用户反馈"**海岸线我测试了一下，看到了**" → 视觉验收过，继续做 W4 本体。

### 做了什么

以前"河"只是**地块上的一个布尔标记**（`t["river"]`），渲染时把整个六边形描一圈蓝边 ——
所以看上去是"**一圈圈蓝格子**"，而不是"一条河"。

- `world_gen`：侵蚀本来就算过"每格往哪流"（`lowest`），但**算完就扔了**。
  现在**留了下来**（`_flow_to`），并在挑出河格之后把每条"河格 → 下游河格"落成**一条河道边**：
  - 边键用 **W1 就定好的格式** `"q,r,d"`，**owner = 两端坐标字典序较小者**，
    `d` = 从 owner 指向另一端的六方向序号（反向用 `(i+3)%6`，已数值验证）。
  - 新增 `WorldGen.edge_key_of(a, b)`（把两端坐标规范化成边键）与 `WorldGen.river_edges(seed)`。
  - 值 = 该格的**流量** → 画线时按它定粗细（大江比小溪粗）。
- `hex_map_view`：`_draw_water_edges()` 里**按边画河道** ——
  只画"**我这一侧拥有**（owner）的那条边"，所以**同一条边只会画一次**（不会两边各画一遍变成双倍粗）。
  地块层不再画蓝色整格圈（统一画普通格线）。

### 实测

- 6 个无头自检全绿（`seed_check` 仍报"河流格 28 个、43% 有相邻河流格"）；
  截图 45 张无报错。
- ⚠️ **河道"像不像一条河"这一条仍要人看**（默认镜头在内陆，河流应当在画面里，
  但我这次没来得及做像素/识图判读 —— 见下）。

### ⚠️ 下一步

1. **人看**：跑游戏看河是不是"一条连续的线"（而不再是"一圈圈蓝格子"）。
2. 河道边**还没写进存档**（`state["edges"]` 仍是空的）—— 现在是每次渲染按种子现算（纯函数、确定）。

## 🔴 用户实测报的 bug（2026-10-13）：**大多数河流在海里**

用户原话：*"我开了两次地图，大多数河流不知道为什么竟然在海里，然后陆地上也通常只有一两条，
而且分隔两地很远，而不是绵延不绝连起来的河流。"*

### 根因（**问题比"画错"更基础**）

**海里也有"流量"** —— 侵蚀是对 `Hex.spiral(MAP_MAX_RADIUS)` **整片（含海）**算汇流的，
而海盆会把大片区域的水汇到一起。于是：

1. "流量前 2%"那批**几乎全是深海格** → **河就挑在海里**；
2. 而且**分界线本身也是按全图（含海）算的** → 被海抬得很高 → **陆地格几乎够不着**，
   所以陆地上只剩一两条、还离得远。

（这是我上一轮只顾着"补到入海"、没检查**起点**造成的 —— 补链路本身没错，但**种子挑错了地方**。）

### 改法

- **只按"陆地格"统计流量分布**，也只允许**陆地格**当河头（`out[k] >= SEA_LEVEL`）。
- 顺流补给到**入海就停**（入海口那一格**不**标成河）—— 免得河边又伸进海里。
- `SEA_LEVEL := 0.36` 提到**文件级常量**（和 `biome_of` 的水线是同一个数）。

### 实测

| 指标 | 修前 | 修后 |
| --- | --- | --- |
| **在海里的河格** | *大多数*（用户实测） | **0** ✓ |
| 河流格 | 42 | **22** |
| 有相邻河格的比例 | 95% | **91%** |

并把这条 bug **固化成断言**（`seed_check`）：**"没有一格河在海里"** ——
以后谁再改回"含海统计"就会立刻红。

### ⚠️ 待用户确认

河现在**是连续的、且一定在陆上**，但总数只有 22 格（约 2~4 条、每条 5~10 格）。
**如果觉得"河太少/太短"**，旋钮就是"陆地流量的百分位"（现在是 2%）——
调大就会多出几条河，调小则河更少更长。**这个属于可逆参数，等用户看过再定。**
### 河多河少的旋钮：用户试 **20%**（2026-10-13）

用户说"太少太短了，尝试一下 20% 的数值如何？"→ 把百分位提成常量 **`RIVER_FLOW_PERCENT`**（默认改成 0.20）。

| `RIVER_FLOW_PERCENT` | 河流格 | 占陆地 | 连链率 | 在海里 |
| --- | --- | --- | --- | --- |
| 0.02（原） | 22 | ~3% | 91% | 0 |
| **0.20（现）** | **169** | **~22%** | 90% | 0 |

→ 现在是一张**树枝状的水系网**（约 1/5 的陆地格带河），而不是"两三条短河"。
**这个数纯口味、可逆**：嫌密就往 0.08~0.10 收，嫌还不够就往 0.35~0.50 放。
⚠️ 注意：河道**不改变地形/地物**（只是给格子打 `river` 标记 + 画边），所以地形与地物分布**完全没动**。

## 🔴 用户用"头尾编号"指出的真问题：**数学上连、视觉上断**（2026-10-13）

用户原话：*"也许他们在数学上有种连在一起的错觉，但是在视觉上是破碎的……一个六边形有六个角
从左上开始，上边 1、2，中间 6、3，下边是 5、4……如果有一条河从左到右途径并上拐，
那么应该是：第一个地块的一条线的头是 5、尾是 4；第二个地块的第一条线头 5 尾 4，
第二条线头 4 尾 3 —— 这样才是连起来了。"*

**他说得对，而且这正是问题所在**：水从一格"进"与"出"用的是六边形的**不同两条边**；
两条边**只有相邻（共顶点）时才接得上**，隔着一个角就**接不上** → 线段之间差一个顶点，
看着就是断的。

### 改法：河道**穿格心**画

不再"画我与下游共享的那条边"，改成**从本格中心连到下游格中心** ——
同一格里"进"和"出"**天然接上**，不可能再断开。

### 验证（识图）

> *"非常成功……线条从一个六边形几何中心直接连到相邻六边形中心，形成连贯的折线，
> 有了'河流流淌'的连续感，消除了之前接不上的断裂感。"*
> *"没有明显的断开……连接性做得很好。"*

### 顺带修掉的一条

**粗细本来全都一样**（识图："粗细和颜色都是一样，像蜘蛛网"）——
因为我用 `flow / 60` 再 clamp，而河格流量普遍远大于 60 → **全部钳到上限**。
改成**对数刻度**（`log(1+flow) / log(1+1000)`），主干与支流才拉得开。

### ⚠️ 识图还提了 3 条（**未做**，留档）

1. **河线从图标上方穿过**（资源/建筑/首都星）：因为穿格心必然经过图标所在的位置。
   要彻底解决得把河画成"格心 → 边中点"的**辐条**（或只在图标下缘走），属**画法**问题。
2. **首都那一格像十字路口**（4 条线汇聚）：那是**汇流**（多条支流并进同一格），本身合理，
   但等粗时看着像枢纽；对数粗细上之后应当改善。
3. **地图边缘的"断头河"**（一条线直插黑色未探索区）：河到世界边界就停了，看着突然。
   要不要在边界收住，等用户看过再定。

# 🔄 河流方案改向（2026-10-13 用户拍板）：**改成《文明6》那种"沿地块边界走"的河**

用户原话：*"不对不对，我想要的不是这种效果，是文明6那种河流……现在的河流生成弃用，
技术上采用这种思路试试：应该先把地形图上的河道读出来，一张河道的路线图，
再把这条水路按照六边形的格式折好，然后放到地图上去。超出边界和陆地的就折断。"*

## 一、为什么现在这种不行（把两件事分清）

- **"穿格心"画法**（今天刚做的）：从一格中心连到下一格中心。它解决了"线段接不上"，
  **但形状是错的** —— 真实的河**不穿地块中间**，而是**走在地块与地块之间**（河两岸是两格地）。
  所以这条路**弃用**。
- 之前"沿边画"之所以会断，是因为**我只画了"我和下游共享的那一条边"**——
  但水从一格"进"与"出"用的是**不同两条边**，两条边若**不相邻（不共顶点）**，线就接不上。
  → **正确做法不是换画法，而是让"这条边 + 下一条边"本身是相邻的边**（在同一个六边形上首尾相接）。

## 二、方案（照用户给的思路，落成可执行步骤）

**第 1 步：读河道**（地形图 → 河道中心线）
- 源数据已经有了：侵蚀里的**汇流网络**（每格 `flow` + 每格"往哪流" `flow_to`）。
- 取"陆地格中流量 ≥ 阈值"的那批当**河道骨架**（阈值就是现在的 `RIVER_FLOW_PERCENT` 旋钮）。
- 顺着 `flow_to` 往下游走，得到**一条条像素空间的折线**（河心线，从源头到入海）。

**第 2 步：折成六边形的走法**（关键一步，也是《文明6》与普通画法的分界）
- 对河心线上的每个采样点：找出它**最靠近的那条六边形边**（即它与哪两格相邻）。
  判据：点落在"两格中心连线的中垂线附近"时，就算它走在这两格之间的边上。
- 相邻采样点若落在**同一条边**上 → 合并；
  落在**相邻的两条边**上（共顶点）→ 直接首尾相接 ✓；
  若跳到了**不相邻的边**（中间隔了一个角）→ **补一条过渡边**（走中间那个角对应的那条边），
  保证整条路**每两步都是相邻边** —— 这正是用户那句"按照六边形的格式折好"。
- 结果 = **一串边键**（`"q,r,d"`，格式 W1 就定好了），天然首尾相接，**视觉上不可能断**。

**第 3 步：贴到地图 + 折断**
- **超出地图边界**的边：丢（用户："超出边界……折断"）。
- **两侧都是水**的边：丢；**进入海里的那一段**：到海岸为止（入海口停在最后一格陆地边）。
  用户："超出……陆地的就折断"。
- **宽度**：按流量分级（对数刻度，今天已做），主干粗、支流细。

**第 4 步：渲染**
- 按边键取那两条边**共用的两个角**，用 `draw_polyline` **一笔画完整条河**（而不是一段段 `draw_line`），
  接缝处用圆角（`draw_polyline` 的 joint 处理），这样连转角都是圆滑的。
- **图层**：河属于"水路"那一层（用户定的最底层，在地物/建筑图标之下）。

## 三、验收

1. **几何断言（可无头测，不靠眼睛）**：边路径里**每相邻两条边必须共顶点**（即"折好"这件事本身）；
   且首尾连通成一条链（不是散段）。**这条断言就是用户那个"头尾编号"的代码版**。
2. **不断**：整条河从源头到入海是**一笔连续的折线**。
