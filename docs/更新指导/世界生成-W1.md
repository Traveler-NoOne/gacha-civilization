# 世界生成 · W1 —— 松绑与数据模型（**观感零变化**）

> 状态：⬜ 未开始（用户将统一审阅）
> 依赖：无（**本项目的第 1 段**）
> 总纲：[世界生成-过程模拟.md](./世界生成-过程模拟.md)

## 一、这一段要干什么

**把地基换掉，但画面一动不动。** 现在的生成器是"**每一格各自算**"（纯函数），
要换成"**先生成整张死地图，再从上面裁一块**"。W1 不写任何新算法，
只做两件事：**拆掉旧约束**、**把新数据结构定死**。

## 二、具体做什么

### 2.2 定死新数据结构（**这一段最重要、也最不可逆的部分**）

| # | 新增/改什么 | 内容 |
| --- | --- | --- |
| 1 | `state["worlds"]` | **每块世界一份配方**：`dir` / `origin` / `seed` / `sim_size` / `climate_size` / `crop_center` / `crop_radius` / `map_radius` / `world_age`（= 侵蚀轮次，见总纲 3.6） |
| 2 | `state["edges"]` | **边的独立集合**，键 `"q,r,d"`；两类边 `river_edge` / `water_edge`；**owner = 两端坐标字典序较小者**；反向 `(d+3)%6` |
| 3 | **方向索引规范表** | 写进 `hex.gd` 的注释：**边 k（顶点 k→k+1）↔ `DIRECTIONS[(−k) mod 6]`**（总纲 3.3 那张表） |
| 4 | `state["tally"]` | 全局增量计数器（先放**敌人数**）。⚠️ **故意不叫 `counters`** —— `unit_db.gd` 里职业数据已经用 `"counters"` 表示**克制关系**（`:68` 等），同名会误导（用户最在意"名字不能误导"）。**只允许单一入口修改** |
| 5 | 稳定度等**全局量** | **确认即可，无需改代码**（见下方"实测结论"） |
| 6 | `SAVE_VERSION` **+1** | 老档按既有策略**直接删除**（提示"存档已过期，请新开一局"） |

> ⚠️ **计数器的纪律**（用户 2026-10-13 定：**不加自检断言，漂移由用户自己抓**）：
> 仍然必须**只走单一入口**（沿用现有 `clear_enemy_tile()` 这类函数）；
> 但**不新增**"计数器 ↔ 枚举对账"的断言。**别偷偷加**——用户明确说这浪费 token。

| 位置 | 内容 |

| `world_gen.gd:65~91` | 侵蚀那段"**固定最大范围**"的注释与 `Hex.spiral(MAP_MAX_RADIUS)` —— 约束拆了以后不再需要 |
| `world_gen.gd:298~300` | "地形/资源 = f(坐标, 世界种子) 的纯函数"那段约定 —— **改写成新约定**（整图可复现） |
| `tests/seed_check.gd` §⑦ | 两条守旧约束的断言："扩张不会改动已有地块"、"新格与标准世界同坐标一致" —— **删**（它们守的东西不存在了） |

> ✅ **实测结论：2.2 第 5 项（稳定度等全局量）不需要改代码。**
> `owned_tiles` / `discovered_tiles` / `free_tiles` / `enemy_tiles`（`game_state.gd:286~319`）
> 与 `player_force` / `enemy_force`（`:395~415`）**本来就遍历整个 `state["tiles"]`**；
> `stability()` 的"地图总格子数"就是 `state["tiles"].size()`（`:434`），
> 敌人数量是 `enemy_tiles().size() + state["threats"].size()`（`:435`）。
> → **多块世界合进同一个字典之后，它们自动就是全局统计**。
> **所以 W1 这里只写一条注释**（"这里**故意**是全局口径，别改成按当前显示的世界统计"），
> **不要动代码** —— 免得白改一遍还引入风险。
>
> 💡 顺带说明**为什么还是要那个 `tally`**：这些函数每次调用都**全表枚举**，
> 而 `stability()` 还会连带调 `player_force` / `enemy_force` / `free_tiles`（= 多次全表扫描）。
> 一块世界 1387 格时无所谓，**拼到 20 块 = 2.7 万格**、又赶上 UI 刷新时就会明显。
> → 用增量维护的 `tally` 顶掉**热路径**上的枚举；上面那些函数**保持原样**（它们仍是"地面真值"）。

## 三、验收

1. **游戏完整可玩**（总规则第 1 条）。
2. **4 个无头自检全绿**（`seed_check` / `fatal_check` / `popup_measure_check` / `dead_ref_check`）。
3. **截图容差对比：45 张里除 `17_dialog_draw`（抽卡随机）外应全部零变化** ——
   这是"**换地基没搬家**"的证据（沿用 1.8.20 定下的 MAD ≤ 2% 规矩）。
4. 老档（`SAVE_VERSION` 旧的）能正确被识别为过期并删除，且**不污染当前局**。

## 四、范围外

- **不动任何生成算法**（板块/气候/河流都在 W2~W4）。
- **不做裁切器**（W5）、**不做拼接**（W7）。
- **不做 (B) 方案的"只存动态叠加"** —— 用户已定全量存地块（总纲 3.5 / 8.3）。

## 五、风险

- **这一段改的是存档格式与共享数据**，一旦定了就别再改（总纲第十二节把"边规范 / 配方字段 / 拼块结构"列为**不可逆**）。
- `edges` 与 `tally` 现在**没有消费者**（要在 W4/W7 才用上）→ W1 只把它们建起来并写清规范，
  **不要为了"看起来有用"就提前接一半**（避免半成品逻辑留在代码里）。
