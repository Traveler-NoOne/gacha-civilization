# 1.8.20.9 · 世界地图随种子变（方案 B）+ 顺手清掉三个新产生的死参数

> 起因：用户读 `world_gen.gd` 时发现 **`_make_tile(c, rng)` 根本没用上 `rng`** ✗ ——
> 地形和基础资源全部来自**坐标哈希**（`Hex.hash01(c, 7)` / `hash01(c, 31)`），
> 也就是**每局地图完全一样**，与 `state["seed"]` 无关。
> 但管线是齐的（`generate()` 专门按种子播了个 rng 再传给 `_make_tile`）→ 说明**当初的意图**是"世界随种子变"。

## 一、方案 B：把种子拌进哈希的盐（不是用 rng 顺序摇）

```gdscript
static func _make_tile(c: Vector2i, world_seed: int) -> Dictionary:
    var r  := Hex.hash01(c, 7  + world_seed)
    var rr := Hex.hash01(c, 31 + world_seed)
```

于是每格的地形/资源是 **`f(坐标, 世界种子)` 的纯函数**：

- **同一个种子 → 同一张世界地图** ✓
- **`expand_map()` 后加出来的那一格，与"一开始就生成这么大"时的同一坐标必然一致** ✓✓
  （纯函数，与生成顺序无关）

**为什么不能改成用 rng 按顺序摇地形** ✗（这是本次最关键的一条）：
那样地形就变成"生成顺序决定"的 —— 扩张时后加进来的同一格会**和初始生成的不一样** ✗。
`hash01(c, seed)` 这条路**两个都要**：既每局不同，又坐标自洽。

## 二、顺手清掉的三个死参数（都是这次改动*新产生*的）

| 位置 | 为什么死了 |
| --- | --- |
| `generate()` 里那个局部 `rng`（原来播种后只喂给 `_make_tile`） | 现在不需要 rng 了 |
| `expand_map(state, rng, rings)` 的 `rng` 参数 | 它只转发给 `_make_tile`，现在不转了 |
| `view_world_page.gd` 的 `_rng()` 帮手 | 它只被 `expand_map(GameState.state, _rng(), 1)` 那一处用，现在不用了 |

（用户刚指出"`_make_tile` 那个 rng 是死的"，所以不能转身又种三个新的。）
两个调用点跟着改：`gacha.gd:289`、`view_world_page.gd:80`。

## 三、自检（本次唯一的自检文件：`tests/seed_check.gd`，在原 10 条后面加了两节）

跑法（**必须用场景跑**，原因见下）：

```
godot --headless --path . res://tests/seed_check.tscn
```

**17 条断言全通过**，新增的 7 条是：

- 换种子 → 世界地图不一样（**这正是本次新做的行为**）
- 换种子 → 地形分布也跟着变
- 不传种子（取时钟）→ 每局也是不同的世界
- 扩张加进来 48 格 / 扩张**不会改动已有地块**（逐格逐字段相同）
- 新格与「标准世界」同坐标一致（纯函数，与生成顺序无关）

## 四、⚠️ 自检踩的坑（很重要，记下来）

第一版自检我用 `godot --headless --script res://tests/seed_check.gd` 跑（`extends SceneTree`）——
**这个跑法不注册 autoload** ✗，于是任何引用 `GameState` 这种单例的生产脚本**编译不过**：

```
SCRIPT ERROR: Identifier not found: GameState
SCRIPT ERROR: Nonexistent function 'generate' in base 'GDScript'
```

结果 `new_game()` 里的**世界生成整个没执行**，而"世界一致 / 世界不同"那几条断言是**空数据下的假通过** ✗✓
（前 10 条 rng 断言不受影响，所以 1.8.20.8 的结论仍然成立）。

**改用场景跑**（`tests/seed_check.tscn`，脚本 `extends Node` + `_ready()`）之后 autoload 正常，才真的测到 ✓。

> 教训：**自检必须用场景跑**（旧自检本来就是那么跑的）；`--script` 只适合完全不依赖 autoload 的脚本。
