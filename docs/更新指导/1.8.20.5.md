# 1.8.20.5 · 补回被 v1.8 重写丢掉的「底部单位条 + 单位操作窗」

> 状态：✅ 已完成
> 起因：用户在 `_refresh_unit_panel()` 的 `if not is_instance_valid(unit_panel_box)` 里加了一行 print，
> 点单位时发现它**每次都打印** —— 顺着查下去，发现那四个成员根本没有被创建过。

## 一、根因：搬了「刷新」，丢了「创建」

`unit_strip` / `unit_strip_row` / `unit_panel` / `unit_panel_box` 这四个成员
在**全项目只被读、从未被赋值**（`_build()` 里只建了工具栏与地图，没有它们）。
于是：

```gdscript
func _refresh_unit_panel() -> void:
	if not is_instance_valid(unit_panel_box):   # ← 永远成立
		return                                   # ← 所以永远在这里返回
```

`_refresh_unit_strip()` 同样。**底部单位条**与**单位操作窗**（攻击 / 移动 / 驻军三个按钮都在窗里，
v1.6.1 的核心战斗交互）从 v1.8 起就再没出现过，而**刷新那半边一直是好的**（写好了没人用）。

**证据**：`docs/版本记录/v1.7.md:133` —— v1.7 时实机确认过「操作窗 **+ 同屏底部 28px 单位条**」生效
→ 说明创建代码当时存在 → 是 **v1.8 的世界页重写**把它丢了。

**为什么一直没被发现**：自检只断言 `sel_uid`（不看面板），而截图那边 `20_unit_panel` 的差异区域
一直只落在**顶栏数字**上 —— 面板区域**从来没变过**，因为它**是空的**。

## 二、补回（按 v1.7 原样）

从 `git show 43c9318:scripts/ui/views/view_world_page.gd`（初始提交 = v1.7.1 现状）取出当年的创建代码
（旧文件 154–178 行），补进现在的 `_build()`（放在 `mv.add_child(map)` 之后 —— 这样两块浮层在地图**之上**，
和 `tile_info_popup` 一个套路；**不放进 map**，因为 map 开了 `clip_contents`）。

- 摆放**全靠锚点**（和 v1.7 一致）：单位条 `CENTER_BOTTOM` + `(0, -10)`；操作窗 `BOTTOM_LEFT` + `(14, -14)`。
- **尺寸/间距全部走 `UI.px` / `UI.fs`**（v1.7 那些是写死值 —— 这几天正在清的正是这类病，不能又种回去）。

### 一处**有意偏离**原样

操作窗原本贴左下角 `(14, -14)`，但**左下角那两个「至宝 / 世界泡」悬浮按钮是 v1.8.7 才加的**（v1.7 时不存在），
实测会被它们压住 → 已抬高到按钮之上：`16(边距) + 40(按钮高) + 14(原间隙) = -70`。

## 三、连带查出来的第二件事（**未修，待定**）

**单位条会「漏」到别的页面**：看「至宝」「日志」时，底部仍挂着「该地块 N 个单位：…」。
原因是 v1.8.8 把世界升格成了 root（其余页面变成盖在它上面的浮窗），**世界页永远可见**，
于是它的子控件（单位条）也一直在；而 v1.7 时视图是整体替换的，切走就跟着没了。

**要修的话得先定一件事**：谁来负责判断"世界正被浮窗盖住"——
① 由 `game_screen` 在开/关浮窗时通知世界页；② 世界页自己判断；③ 别的方案。
这是个所有权/耦合的选择，**留给用户定**。
