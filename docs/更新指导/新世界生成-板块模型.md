## 一、四轮流水线 + 轮次契约

**"不许干什么"比"要干什么"更重要** ✓✓ —— W 计划就是每一段什么都干一点才打架的 ✗。

| 轮 | 输入 | 输出 | **不许干** |
| --- | --- | --- | --- |
| **1 · 板块** | 世界种子 | `plate` 表：每格 `{id, kind}`（大洋 / 大陆） | 不动高度 ✗ 不定地形 ✗ 不碰气候 ✗ |
| **2 · 运动** | plate 表 + 种子 | `motion` 表 ＋ `edge` 表 ＋ **构造高度场** | 不定气候 ✗ 不落 `terrain` ✗ |
| **3 · 地貌单元** | 高度场 + edge | `landform` 表（岛弧 / 裂谷 / 山脉 / 高原 / 海岭 / 海沟…） | 不碰 `terrain` / `cover` ✗ 不动气候 ✗ |
| **4 · 气候** | 高度 + 海陆 | `temp` 场 ＋ `precip` 场 ＋ 柯本表 | **不改高度** ✗ 不落 `terrain` ✗ |
| **落成轮** | 上面全部 | `terrain` ＋ `cover`（旧格式 ✓） | 不引入任何新字段 ✗ |

## 二、每一轮具体怎么做

### 第 1 轮：切蛋糕 = **Voronoi 归属**（不是"先有板块再切" ✗）

```
1. 由世界种子决定 N 个种子点（可复现 ✓）
2. 每一格：离哪个种子点最近 → 归那个板块（= Voronoi / 泰森多边形 ✓）
3. 给每个板块定类型：大洋 / 大陆（按面积比例或直接掷 ✓ 也要确定可复现 ✓）
```
- 让边界**不像直边蛋糕** ✓（真实板块边界是弯的 ✓）：**加权距离** ✓ 或**把种子点松弛几轮** ✓
- ⭐ 这天然满足项目的**纯函数约定** ✓（`f(坐标, 种子)` ✓ 可复现 ✓ 扩张一致 ✓✓）

### 第 2 轮：运动 → 地形（**一张 3×3 规则表** ✓）

给每个板块一个**运动向量** ✓（相邻板块向量之差 → 边界类型 ✓）：

| 边界类型 | 结果 |
| --- | --- |
| 大陆 ↔ 大陆（**碰撞** ✓） | 造山：山脉 / 高原 ✓ |
| 大洋 ↔ 大陆（**俯冲** ✓） | **海沟 ＋ 大陆边缘山脉**（安第斯型 ✓）；大陆架被挤**窄** ✓ |
| 大洋 ↔ 大洋（**俯冲** ✓） | **岛弧**：一串浅海 ＋ 岛 ✓ |
| 分离边界（**洋中脊** ✓） | 海岭 ✓ |
| 大陆内部张裂（**裂谷** ✓） | 断层崖 ＋ 中间下陷 ✓（东非大裂谷 ✓） |

⭐ 白送的真实感 ✓：**被动边缘（大西洋型）→ 宽大陆架** ✓ ／ **主动边缘（太平洋型）→ 窄架 ＋ 海沟** ✓

### 第 3 轮：地貌单元

- **岛屿架 / 岛架**：第 2 轮岛弧处出现的浅海 ✓ —— **不一定有岛** ✓ 也可能是海隆 ✓
  → **海隆与岛屿架归一类 ✓（命名取"岛屿架"）** ✓✓ 理由：玩家看到的就是"洋中浅水" ✓ 区分它俩**没有玩法意义** ✓
- **大洋岛**：少数岛屿架上"挤"出来的 ✓ 或**火山**直接喷出来的（没有岛屿架围着 ✓）
- 大陆侧：**谷地 / 山峰 / 高原** ✓
- **大陆坡**：并入**大陆架外缘** ✓（一两格宽 ✓ 视觉够用 ✓ 单独立类不值）

### 第 4 轮：柯本气候

柯本本身只是**一张查表** ✓（和你已有的 `BIOME_TABLE` 一个套路 ✓）—— 真正要设计的是它的**两个输入**：

- **温度** = 纬度（离赤道）＋ 高度衰减 ✓
- **降水** = 气压带 / 风带 ＋ **地形雨**（迎风坡多 ✓ 背风坡少 ✓）✓ 或者先简化为一张噪声 ✓

> 建议：**温度场、降水场各算一张表** ✓ 再查柯本 ✓ → 两张中间表都能**单独画出来看** ✓✓

## 附录：为什么用**标签**而不是**继承**

| | 类继承 | **标签法（本方案）** |
| --- | --- | --- |
| 表达"顺序 / 分轮次" | ✗ 继承是**编译期**定死的 ✗ 而分类是**生成期**才确定的 ✗ | ✓ 每轮往同一格**盖一个章** ✓ 顺序天然由流水线表达 ✓ |
| 一格同时属于多个维度 ✗（大洋地壳 ＋ 岛弧 ＋ 热带） | ✗ **一棵树装不下** ✗（一个节点只有一个父 ✗） | ✓ 每轮各加一层标签 ✓ 多维度天生支持 ✓ |
| 地块是**数据**（1388 格 ✓ 纯 Dictionary ✓） | ✗ 每格一个对象 ✗ 又费又难存档 ✗ | ✓ 就是 Dictionary ✓✓ |
| 调试 | ✗ 错在哪个类不好看 ✗ | ✓ 每轮中间表都能打出来看 ✓✓ |
| 技术门槛 | 需要熟悉继承 / 虚函数 | ✓ 字符串 ＋ enum ＋ 表 ✓✓ |

**判据（记住这一句）** ✓：**继承管"行为" ✓ 标签管"数据"** ✓
- 建筑有行为（每级产量 ✓ 升级消耗 ✓ 能不能建 ✓）→ 用类 / `Resource` 是对的 ✓（项目里 `BuildingDef` 就是这么做的 ✓✓）
- 位阶 ✓ 职业 ✓ 科技 ✓ 地形 ✓ 板块 ✓ → 纯数据 → **用表** ✓（`UnitDB.RANKS` ✓ `Consts.TECHS` ✓ `BIOME_TABLE` ✓ 都是这个套路 ✓✓）

## 附录二：**为什么要"真实地理"**（用户 2026-10-15 说清的动机 ✓ 这是本系统的立项理由 ✓）

> 用户原话大意："现实化的地理**具备战略意义** —— 大规模的山脉、裂谷，或者长江这种，是**天然要塞 / 地理长城** ✓
> 在**阻击终极威胁**这件事上利用得好会非常有用 ✓。

### 落到本作里，具体是什么（不必新系统 ✓ 复用今天定的分类 ✓）

> 强调一件事：所有的地貌并非强制生成，都看运气。包括子地貌：隘口，长山系。

- **山脉** → 不可通行或极贵 ✓ ＋ 相邻格防御加成 ✓；**"隘口"＝山脉的缺口** ✓ 未来计划：需要消耗巨量移动力，例如6点以上，并且基于速度值给予debuff，结算时若是单位无论敌我，存在于山脉上，会减少血量。
- **山地**（`upland`）→ 山脉的**低配版**：**能通行** ✓，代价高于丘陵、低于山脉（2026-10-22 用户定："山地和山脉相比，可以通行"）；
  生成时由 `Peaks.thin_mountains()` 把**太胖的山团**降级打出来 ✓（贴高原的转高原、其余转山地 ✓）
- **裂谷** → 横向隔断 ✓ 跨越点极少 ✓（陆上的"长城" ✓）未来计划：同山脉，但不会削减血量。
- **大河** → 抄长江的**双面性** ✓：**运输动脉 ＋ 天然分界** ✓（渡河成本高 ✓）未来计划：速度值不够的话，会无法上岸，无法逆流，只能被动或主动顺流而下，对于部分单位甚至会大量削减血量。
- **深海 / 浅海** → 未来计划：除非单位有独特机制或特殊天赋，例如单位是船。以及进入海洋后不是船会持续削弱生命，编队内有船的话，优先消耗船的附加数值，补给。如果不是船且当前地块存在洋流则会被洋流带走，无法主动移动，如果没有洋流，则可以寻找海岸上陆，在科技树不够时，进入深海地块单位会直接迷失，虽然还在地块上，但是玩家已经看不见单位了，此时单位会被洋流带走或者自主随即移动，回到存在视野的浅海地块时，则会自动提醒玩家单位回归。如果单位未能在生命削减完前回到陆地上，则会直接死亡，同时通知玩家：生死不明，大抵是死了。

### M1 · 第 1 轮：板块（**只做这个** ✓）

**新文件**：`scripts/worldgen/plates.gd`（`class_name Plates` ✓）

```gdscript
const PLATE_COUNT := 10      # 半径 21 时大概这么多块（可调 ✓）
const RELAX_ITERS := 2       # Lloyd 松弛次数：让边界从"直边蛋糕"变弯 ✓
const CONTINENT_RATIO := 0.35  # 大陆地壳占多少（按面积 ✓ 且优先给靠中心的块 ✓）

## 返回：
## { "cell_plate": { "q,r": plate_id },        # 每格归属 ✓
##   "plates": [ {id, kind, area, center, seeds}, ... ] }   # kind = "continent" / "ocean"
static func build(world_seed: int, radius: int) -> Dictionary
```

**做法（三步 ✓ 都在 `build()` 里 ✓）**
1. **撒种子点** ✓：`var rng := RandomNumberGenerator.new(); rng.seed = world_seed` ✓
   （**GDScript 的 RNG 是确定性的** ✓ 同种子同结果 ✓✓ —— 这就是"纯函数"的实现方式 ✓）
   在半径内撒 `PLATE_COUNT` 个点 ✓（避开重复 ✓）
2. **Voronoi 归属** ✓：遍历 `Hex.spiral(radius)` 的**固定顺序** ✓（顺序固定 = 结果固定 ✓），
   每格取**最近的种子点** ✓（`Hex.distance` ✓）→ 记 `cell_plate[key] = id` ✓
3. **松弛 2 轮** ✓（Lloyd ✓）：把每块所有格的中心当**新种子点** ✓ → **重算归属** ✓
   → 边界就从"直边"变**弯** ✓✓（这是"像大陆"的关键一步 ✓）
4. **定类型** ✓：按面积从大到小 ✓ ＋ **越靠中心的块越可能是大陆** ✓
   （前 `CONTINENT_RATIO` 的块 → `continent` ✓ 其余 `ocean` ✓）
   → 于是"**大陆在中间、大洋在外圈**" ✓✓ 和旧系统的直觉一致 ✓ 但**形状是自然长出来的** ✓

**调试绘制** ✓：**新写** `scripts/worldgen/debug_draw.gd`（`extends Control` ✓ 只给预览用 ✓）
- `_draw()` 按 `pass` 画：`plates` 模式 → 每格填**板块色** ✓（大陆暖色 ✓ 大洋冷色 ✓）＋ 块边界描线 ✓
- ✗ **不要**去改 `HexMapView` ✗（那是游戏绘制 ✓ 别混进来 ✓）
- `preview.gd` 里加参数 `pass` ✓（`"terrain"` = 老样子 ✓ ／ `"plates"` = 板块图 ✓）

**验收（出图 ✓）**：连出 **10 张以上不同种子**的板块图 ✓ 依次看：
- 大陆**在中间**吗 ✓ 大洋在外圈吗 ✓
- 块**大小**像不像板块（不是一堆碎块 ✗ 也不是两三块巨无霸 ✗）
- 边界**弯不弯** ✓（还是直边蛋糕 ✗ → 加松弛次数 ✓）
- 块数量像不像地球的十来个 ✓

### M2 · 第 2 轮：运动 → 高度场

**新文件**：`scripts/worldgen/tectonics.gd`
```gdscript
## 返回 { "heights": {key: float}, "edges": {key: "collision"|"subduction"|"arc"|"rift"|"ridge"|""},
##        "motion": {plate_id: Vector2} }
static func build(plates: Dictionary, world_seed: int) -> Dictionary
```

**做法**
1. **每块一个运动向量** ✓（确定性随机方向 + 速度 ✓）
2. **找边界** ✓：遍历格子的 6 邻 ✓，`plate_id` 不同 → 这格是边界 ✓
3. **判类型**（两块的相对运动 ✓ 用点积 ✓）：
   - `dot < 0`（**相向**）→ 汇合 ✓：大陆-大陆 → **`collision`（造山）** ✓；大洋-大陆 → **`subduction`（海沟＋边缘山脉）** ✓；大洋-大洋 → **`arc`（岛弧）** ✓
   - `dot > 0`（**相背**）→ 分离 ✓：大陆 → **`rift`（裂谷）** ✓；大洋 → **`ridge`（洋中脊）** ✓
4. **高度场** ✓：基础高度按地壳类型 ✓（大陆 0.55~0.70 ✓ 大洋 0.15~0.35 ✓）
   ＋ 边界修正 × **距离衰减**（1~4 格线性 ✓）：
   - `collision` **+0.30** ✓（山系成**带** ✓ 不是一颗颗孤岛 ✓）
   - `subduction` 大洋侧 **−0.25**（海沟 ✓）／大陆侧 **+0.20**（安第斯 ✓）

## 八、水系与洋流（用户 2026-10-15 提出 ✓ 定位 **M6** ✓ 现在只定几何 ✓ 不实现 ✗）

### 用户的模型（**几何是对的 ✓✓**）

- **水中心 = 六边形的角** ✓（截图里那些圆点 ✓）→ 一个水中心 = **3 个地块的交汇点** ✓
  → 所以它**恰好有 3 个方向** ✓✓（这就是三角 / 蜂窝**顶点格** ✓
    真实水系本来就长在"边"上而不是"格子里" ✓✓ —— 这也是当年 W 计划想做、然后崩掉的那条路 ✗）
- 每个水中心：**水量** ＋ **来源方向**（不可逆流 ✓）
- 按**柯本**：蒸发一部分 ✓ 分给另外两个口 ✓ 自己留一部分 ✓
- **流速** = 相邻两水中心之间的水量 / 周期 ✓ → 与单位速度值比较 ✓ 顺流减移动力 ✓
- **跨地块时**按方向查这段流速 ✓ 过大 → 掉血判定 ✓ 甚至被冲走一格 ✓
- 水量过高 → **洪灾**（按柯本 ✓）／过低 → **干涸** ✓
- **独立于地块** ✓ 另一套"点网格"（和地块字典并列 ✓ 互不干扰 ✓✓）

### 我的判断：**现实 ✓ 而且开销极低 ✓**（数据说话）

| 项 | 数字 |
| --- | --- |
| 水中心数量 | ≈ **2 × 地块数** ≈ **2800**（半径 21） |
| 每中心每周期 | 3 邻居 ＋ 柯本查表 ＋ 几个浮点 ≈ **20 次运算** |
| 每周期总量 | ≈ **50k 次浮点** ✓ —— GDScript 里**几毫秒** ✓✓（比现在 `Threats.evolve` 遍历 1387 格还便宜 ✓） |
| 存档增量 | 2800 × 几个 float ≈ **30~60 KB** ✓ 可接受 ✓ |

→ **花销从来不是问题 ✓** 真正的问题是"**模型选哪个**" ✗（见下 ✓）

### ⚠️ 两种计算方式**不是实现选择**，是**两种物理模型** ✗

| | **A 双缓冲（扩散）** | **B 沿程传播（汇流）** |
| --- | --- | --- |
| 做法 | 每中心两桶 `water` / `next_water` ✓ 用**当前**算**下周期** ✓ 一遍遍历 ✓ 无排序 ✓ 无连锁 ✓ | 按**高度**定流向 → 求**拓扑序** → 从源头（降雨 / 地下水）往下传 ✓ |
| 复杂度 | O(V) ✓ 最简单最稳 ✓✓ | O(V log V) ✓ 也不贵 ✓ 但**要先有高度场** ✗ ＋ 要处理**汇集成环** ✗ |
| 会得到什么 | 水向各方向**摊开** ✓ → 像**湖 / 海** ✓ | 水往低处**汇** ✓ 汇流量决定河宽 ✓✓ → **才产生"河"** ✓✓ |
| 适合 | **洋流** ✓✓（洋流本来就是**环流** ✓） | **陆地水系（长江！）** ✓✓ |

> ⭐ **建议：不是二选一 ✗ 而是分工** ✓
> **陆地水走 B（汇流）** ✓ —— 河 ✓ 流速 ✓ 洪灾 ✓ 干涸 ✓
> **海洋水走 A（扩散）** ✓ —— 洋流环流 ✓
> → 所以**不必**做成设置项 ✗（玩家不该选"水的物理模型" ✗）；
>   如果担心性能 ✓ 设置里给一档「**水系统：关 / 简 / 全**」即可 ✓（性能档 ✓ 不是模型选择 ✓）

### 三个必须提醒的细节 ✗

1. **"流速"要除以断面** ✗ —— 水量/周期 = **流量** ✓，不等于速度 ✓；
   速度 ≈ **流量 / 河宽** ✓（河宽可由汇流量定 ✓✓）＋ 与单位速度比较时用后者 ✓
2. **"分配比例"别由柯本决定** ✗ —— 真实里**流向由地形（高度）定** ✓ 柯本只决定**蒸发率** ✓✓
   （水不会因为"气候"就往某个方向流 ✓）
3. **"整条水路干涸" → 改成"下游断流"** ✗ —— 上游有雨就还会流 ✓ 干涸只应**往下游传** ✓✓

### 洋流（基于水路推出来的方案 ✓）

- 同一套**顶点网格** ✓ 但走 **A 扩散** ✓
- 驱动 = **风带**（纬度 ✓ 柯本那一步已经有 ✓）＋ 海陆阻挡（贴着大陆走 ✓）＋ 可选科里奥利 ✓
- 结果天然是**环流** ✓（洋流是环 ✓ 不是"从高到低" ✓）
- 用途 ✓：海上单位被带偏 ✓（正好接上"迷失 / 被冲走"那条玩法 ✓✓）

### 时序（**别现在做** ✗）

| 依赖 | 为什么 |
| --- | --- |
| 汇流要**高度场** | 没有高度就不知道水往哪流 ✓ → 得等 **M2** ✓ |
| 蒸发要**气候** | 柯本还没做 ✓ → 得等 **M4** ✓ |

→ 所以水系是 **M6** ✓，**M1~M4 之前不要碰** ✗
→ ✅ 但**有一小块现在就能单独做** ✓：**顶点网格本身**（"一个水中心 ↔ 3 个邻居"的构造 ＋ 可视化）
   它**只依赖六边形几何** ✓ 不依赖地形 / 气候 ✓✓ → 做完就能在图上看到你截图里那些圆点 ✓
   （`Hex.corners()` 给角坐标 ✓ 但**没有顶点拓扑** ✗ → 得自己建 ✓
   顶点键最省事的做法 = **把这格与相邻两格的三个键排序后拼起来** ✓ 唯一且稳定 ✓✓）
