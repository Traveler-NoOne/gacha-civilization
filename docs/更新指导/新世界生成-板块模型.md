## 〇、三条不变量（违背其中任何一条就停手 ✗）

1. **新系统独立成目录** ✓ 全程**不改**旧的 `WorldGen` / `TileDef` / `TileManager` ✗
2. **对外只做一件事** ✓：**产出与现在一模一样的 `tiles` 字典** ✓✓
   → 不新增 `state` 结构 ✗ 不改存档格式 ✗ 不改绘制 ✗ 不改任何调用方 ✗
   → 于是"迁移" = `new_game()` 里**换一行** ✓✓ 旧系统一个字都不用改 ✓ 不满意直接切回 ✓
3. **不上地图的东西不进地块** ✓ —— 板块、运动、边界类型都是**生成器内部中间数据** ✓
   （与现有 `_eroded` 高度表 ✓ `_river_keys` 河格表 ✓ 完全同类 ✓ 那两样也不上地图 ✓）

> ✗ **明确不做**：不给每个分类建 `class` / 用继承 ✗（见文末「为什么用标签不用继承」）

## 一、四轮流水线 + 轮次契约

**"不许干什么"比"要干什么"更重要** ✓✓ —— W 计划就是每一段什么都干一点才打架的 ✗。

| 轮 | 输入 | 输出 | **不许干** |
| --- | --- | --- | --- |
| **1 · 板块** | 世界种子 | `plate` 表：每格 `{id, kind}`（大洋 / 大陆） | 不动高度 ✗ 不定地形 ✗ 不碰气候 ✗ |
| **2 · 运动** | plate 表 + 种子 | `motion` 表 ＋ `edge` 表 ＋ **构造高度场** | 不定气候 ✗ 不落 `terrain` ✗ |
| **3 · 地貌单元** | 高度场 + edge | `landform` 表（岛弧 / 裂谷 / 山脉 / 高原 / 海岭 / 海沟…） | 不碰 `terrain` / `cover` ✗ 不动气候 ✗ |
| **4 · 气候** | 高度 + 海陆 | `temp` 场 ＋ `precip` 场 ＋ 柯本表 | **不改高度** ✗ 不落 `terrain` ✗ |
| **落成轮** | 上面全部 | `terrain` ＋ `cover`（旧格式 ✓） | 不引入任何新字段 ✗ |

## 二、每一轮具体怎么做

### 第 1 轮：切蛋糕 = **Voronoi 归属**（不是"先有板块再切" ✗）

```
1. 由世界种子决定 N 个种子点（可复现 ✓）
2. 每一格：离哪个种子点最近 → 归那个板块（= Voronoi / 泰森多边形 ✓）
3. 给每个板块定类型：大洋 / 大陆（按面积比例或直接掷 ✓ 也要确定可复现 ✓）
```
- 让边界**不像直边蛋糕** ✓（真实板块边界是弯的 ✓）：**加权距离** ✓ 或**把种子点松弛几轮** ✓
- ⭐ 这天然满足项目的**纯函数约定** ✓（`f(坐标, 种子)` ✓ 可复现 ✓ 扩张一致 ✓✓）

### 第 2 轮：运动 → 地形（**一张 3×3 规则表** ✓）

给每个板块一个**运动向量** ✓（相邻板块向量之差 → 边界类型 ✓）：

| 边界类型 | 结果 |
| --- | --- |
| 大陆 ↔ 大陆（**碰撞** ✓） | 造山：山脉 / 高原 ✓ |
| 大洋 ↔ 大陆（**俯冲** ✓） | **海沟 ＋ 大陆边缘山脉**（安第斯型 ✓）；大陆架被挤**窄** ✓ |
| 大洋 ↔ 大洋（**俯冲** ✓） | **岛弧**：一串浅海 ＋ 岛 ✓ |
| 分离边界（**洋中脊** ✓） | 海岭 ✓ |
| 大陆内部张裂（**裂谷** ✓） | 断层崖 ＋ 中间下陷 ✓（东非大裂谷 ✓） |

⭐ 白送的真实感 ✓：**被动边缘（大西洋型）→ 宽大陆架** ✓ ／ **主动边缘（太平洋型）→ 窄架 ＋ 海沟** ✓

### 第 3 轮：地貌单元

- **岛屿架 / 岛架**：第 2 轮岛弧处出现的浅海 ✓ —— **不一定有岛** ✓ 也可能是海隆 ✓
  → **海隆与岛屿架归一类 ✓（命名取"岛屿架"）** ✓✓ 理由：玩家看到的就是"洋中浅水" ✓ 区分它俩**没有玩法意义** ✓
- **大洋岛**：少数岛屿架上"挤"出来的 ✓ 或**火山**直接喷出来的（没有岛屿架围着 ✓）
- 大陆侧：**谷地 / 山峰 / 高原** ✓
- **大陆坡**：并入**大陆架外缘** ✓（一两格宽 ✓ 视觉够用 ✓ 单独立类不值）

### 第 4 轮：柯本气候

柯本本身只是**一张查表** ✓（和你已有的 `BIOME_TABLE` 一个套路 ✓）—— 真正要设计的是它的**两个输入**：

- **温度** = 纬度（离赤道）＋ 高度衰减 ✓
- **降水** = 气压带 / 风带 ＋ **地形雨**（迎风坡多 ✓ 背风坡少 ✓）✓ 或者先简化为一张噪声 ✓

> 建议：**温度场、降水场各算一张表** ✓ 再查柯本 ✓ → 两张中间表都能**单独画出来看** ✓✓

## 三、⚠️ 三种"谷"不要混（用户 2026-10-15 指出的 ✓ 已更正）

中文一个"谷"字盖了**三种不同成因** ✗：

| 名字 | 成因 | 归哪一轮 | 长什么样 |
| --- | --- | --- | --- |
| **裂谷 / 地堑**（东非大裂谷 ✓） | **张裂（构造）** ✓ | **第 2 轮** ✓ | 两条**平行崖线**夹一条平坦洼地 ✓ |
| **海沟**（马里亚纳 ✓） | **俯冲（构造）** ✓ | **第 2 轮** ✓ | 细长、极深 ✓ 沿大陆边缘 ✓ |
| **峡谷 / 河谷**（科罗拉多 ✓） | **侵蚀（水文）** ✓ | **气候之后那一轮** ✓ | **蜿蜒** ✓ 上游窄下游宽 ✓ |

→ 构造谷与侵蚀谷**都保留** ✓ 成因不同 ✓ **视觉也不同** ✓✓（分开做反而更好看 ✓）

## 四、代码结构与接口

```
scripts/worldgen/            ← 新目录（独立的一代生成器 ✓ 想整个删掉就删目录 ✓）
├─ plates.gd        第1轮：种子点 + Voronoi + 板块类型
├─ tectonics.gd     第2轮：运动向量 + 边界类型 + 3×3 规则表
├─ terrain_pass.gd  第3轮：构造结果 → **高度场**（出口正好喂给现有的 biome 表 ✓✓）
├─ climate.gd       第4轮：温度 / 降水 → 柯本表
└─ builder.gd       总控：按轮次调用 → 产出 `tiles`（旧格式 ✓）
```

**衔接上的好消息** ✓：第 3 轮的出口是**高度场** ✓ —— 而 `TileDef.biome_of(高度, 湿度)` **已经在等这个了** ✓✓
→ 也就是说：**新系统只需要换掉"高度从哪来"** ✓ 地形 / 地物 / 资源那套**几乎原样复用** ✓✓

## 附录：为什么用**标签**而不是**继承**

| | 类继承 | **标签法（本方案）** |
| --- | --- | --- |
| 表达"顺序 / 分轮次" | ✗ 继承是**编译期**定死的 ✗ 而分类是**生成期**才确定的 ✗ | ✓ 每轮往同一格**盖一个章** ✓ 顺序天然由流水线表达 ✓ |
| 一格同时属于多个维度 ✗（大洋地壳 ＋ 岛弧 ＋ 热带） | ✗ **一棵树装不下** ✗（一个节点只有一个父 ✗） | ✓ 每轮各加一层标签 ✓ 多维度天生支持 ✓ |
| 地块是**数据**（1388 格 ✓ 纯 Dictionary ✓） | ✗ 每格一个对象 ✗ 又费又难存档 ✗ | ✓ 就是 Dictionary ✓✓ |
| 调试 | ✗ 错在哪个类不好看 ✗ | ✓ 每轮中间表都能打出来看 ✓✓ |
| 技术门槛 | 需要熟悉继承 / 虚函数 | ✓ 字符串 ＋ enum ＋ 表 ✓✓ |

**判据（记住这一句）** ✓：**继承管"行为" ✓ 标签管"数据"** ✓
- 建筑有行为（每级产量 ✓ 升级消耗 ✓ 能不能建 ✓）→ 用类 / `Resource` 是对的 ✓（项目里 `BuildingDef` 就是这么做的 ✓✓）
- 位阶 ✓ 职业 ✓ 科技 ✓ 地形 ✓ 板块 ✓ → 纯数据 → **用表** ✓（`UnitDB.RANKS` ✓ `Consts.TECHS` ✓ `BIOME_TABLE` ✓ 都是这个套路 ✓✓）

## 附录二：**为什么要"真实地理"**（用户 2026-10-15 说清的动机 ✓ 这是本系统的立项理由 ✓）

> 用户原话大意："现实化的地理**具备战略意义** —— 大规模的山脉、裂谷，或者长江这种，是**天然要塞 / 地理长城** ✓
> 在**阻击终极威胁**这件事上利用得好会非常有用 ✓。而《文明 6》里**没有这种感觉** ✓ 很少有人说地理被利用 ✓。"

### "地理 ＝ 战略"成立的四个条件（本作**四条全中** ✓）

| 条件 | 为什么《文明 6》不成立 ✗ | 本作为什么成立 ✓ |
| --- | --- | --- |
| **① 威胁有方向** | 敌人从四面来 ✓ 还能跨海 / 空投 ✗ | **终极威胁先游荡 N 周期再直扑首都** ✓ 推进**沿地面** ✓ |
| **② 防守方有边境线** | 城市是**孤立点** ✗ 中间大片无人地带 ✗ | **领地必须相邻扩张** ✓ → 领土**连成一片** ✓ 守的是"线" ✓ |
| **③ 绕路贵到离不开** | 移动 2~3 格 ✓ 绕一下无所谓 ✗ | **周期制 ＋ 行政点数** ✓ 绕路要花好几个周期 ✓ 而威胁**在计时** ✓ |
| **④ 通路稀缺** | 到处都能走 ✗ | **深海 / 浅海 / 山脊** 天然稀缺 ✓（登陆点 ✓ 隘口 ✓） |

### 落到本作里，具体是什么（不必新系统 ✓ 复用今天定的分类 ✓）

- **山脉** → 不可通行或极贵 ✓ ＋ 相邻格防御加成 ✓；**"隘口"＝山脉的缺口** ✓ 由生成器保证**至少留一条** ✓
- **裂谷** → 横向隔断 ✓ 跨越点极少 ✓（陆上的"长城" ✓）
- **大河** → 抄长江的**双面性** ✓：**运输动脉 ＋ 天然分界** ✓（渡河成本高 ✓）
- **深海 / 浅海** → **只有浅海能登陆** ✓ → 深海就是**海上的墙** ✓✓（今天的"深海 / 浅海"分类**直接复用** ✓）
- ⭐ **可读性**：迷雾里也要能看出"**这里是唯一隘口**" ✓ —— 否则玩家不知道哪块地重要 ✓（《文明 6》的另一半问题就在这 ✗）
- ⭐ **侦察有用了**：威胁的进攻方向**在生成时就定了** ✓ → **探路本身就是战略** ✓（正好给"迷雾 ＋ 侦察"一个核心用途 ✓✓）
- ⭐ **一条可验收的质量判据**（用户 2026-10-15 举的例子 ✓）：
  **科迪勒拉山系**那种 —— **一条足够长、连续、能整段封住一侧的长山系** ✓✓
  → 生成器的目标不是"到处有点山" ✗ 而是"**存在能封住一整个侧翼的山墙**" ✓
  → 验收时就这样问：**这张图有没有值得守的地方**？如果没有 ✗ 就是生成器不合格 ✓
  （但记住下面的陷阱 ✓：山墙是"代价极高" ✓ 不是"绝对封死" ✗）

### 与既有原则的关系（这条最漂亮 ✓）

项目原则第 8 条：**"地图按真实地理过程形成；参数只按真实感设，不为平衡而调"** ✓✓
→ **今天这段对话就是它的注脚** ✓：真实过程**自然会长出**隘口 / 分界 / 登陆点 ✓
→ **战略意义是副产品** ✓✓ —— "真实"和"有战略"在这里**不矛盾** ✓✓ 因为真实世界的地理本来就有战略意义 ✓

### ⚠️ 一个要防的陷阱

**别让要塞变成"绝对阻挡"** ✗ —— 真实地理里走不通的地方很多（喜马拉雅 ✓）
但游戏里一旦出现"**唯一的那一条缝**" ✗ → 最优解只剩"堵住它" ✗ → 之后所有玩法都围着那一格转 ✓（城塞流被诟病的原因 ✓）
→ **原则**：地形给的是"**减缓 ＋ 代价**" ✓ 不是"**绝对禁止**" ✓✓（永远存在一条**代价高昂**的路 ✓）

### 时序（别现在做 ✗）

这套东西要等"**多格地图 ＋ 单位在外走动**"足够厚才看得出效果 ✓
→ 现在**只要把地形生成对**（板块 ✓ 造山 ✓ 裂谷 ✓ 河 ✓）✓ **战略意义是后面用规则激活的** ✓✓
