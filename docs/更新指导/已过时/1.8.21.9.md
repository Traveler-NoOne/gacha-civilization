## 三、写 README 时最容易犯的三个错（写明给将来的自己）

1. **不要把"这次清理了什么"写进 README** —— 那是版本记录的内容，README 只描述现状。
2. **不要手写版本号**：`DEMO_VERSION_FULL` 是唯一来源，README 抄一份就一定会再次漂掉。
3. **不要在 README 里列命令清单后就不管它**：列进去的每个命令，写完**立刻照着跑一遍**
   （这次失真就是因为列了 10 套、删了 9 套，而没人再跑过）。

## 四、版本记录落账（**新增**，不是修改）

> ⚠️ `1.8.21.7` 的规矩是"不动 `docs/版本记录/`" —— 那指的是**不修改既有历史**。
> **新增**一个本版本的条目是既定流程（每个版本都要归档，方便追溯"为什么"）。

1. 新增 `docs/版本记录/v1.8.21.md`：这一版做了什么（代码修正 + bug 清单归零 + 文档对齐）、
   **每个决定的"为什么"**、以及被否掉的东西（例如 `1.8.21.7` 第三节那两件事的拍板结果）。
2. 在 `docs/版本记录/README.md` 的索引表里加一行。
3. **不修改** `v1.8.md` 及更早的任何文件。
