# 1.8.20.10 · 致命错误码机制 + 地图缺地块时不再静默空白

> 起因：用户问 `_visible_tiles()` 开头那个 `if not GameState.state.has("tiles"): return out`：
> 「正常情况下它该被触发吗？如果不应该，那就该加报错，而不是只返回空值。」
> 并在批注里给了**比我第一版计划更好**的方向：
> **触发这种错误时后续游戏本来也走不下去 → 应该报一个错误代码、然后结束进程**；
> 玩家重启反而可能自愈；**而不是就着错误继续跑**（勉强跑通、问题没解决、还可能引发别的错）。

## 一、为什么该 fail-fast（先摆事实）

| 事实 | 位置 |
| --- | --- |
| `state` 初始是空字典 | `game_state.gd:20` |
| `new_game()` 的 state 字面量**自带** `"tiles": {}` | `game_state.gd:62` |
| 真正填地块的是 `WorldGen.generate(state)` | `game_state.gd:100` → `world_gen.gd:38` |
| `_visible_tiles()` 只在 `_draw()` 里被调 → **每帧都跑** | `hex_map_view.gd:106` |

1. **正常情况下它永远不该触发**（`state` 空只出现在 autoload 启动瞬间，UI 来不及画）。
2. **旧兜底拦不住真正的病灶** ✗：因为 state 字面量自带 `"tiles": {}`，
   「世界生成没跑成」时 `has("tiles")` 仍返回 **true** → 兜底放行 → **地图空白、零报错**。
   （1.8.20.9 见过同类：`--script` 跑时 autoload 没注册、`generate` 整个没执行，而自检照样"通过"。）

## 二、建了机制（三样）

1. **`scripts/core/fatal.gd`**（`class_name Fatal`，与 `UIKit`/`Consts` 同规格的静态类）
   - `const CODES := { "E-MAP-001": "…含义…" }` —— **码表放代码里**，报错时自动带上含义，不用翻文档。
   - `Fatal.fatal(code)`：`push_error("[致命 <码>] <含义>")` → 然后 `get_tree().quit(1)` 结束进程。
   - `suppress_quit` / `last_code` / `count` 三个 static，给自检用（不然测试进程会被真的杀掉）。
2. **`docs/错误代码.md`** —— 给人和玩家看的对照表（码 / 含义 / 触发位置 / 可能原因 / 怎么办），
   并写明维护约定：**加码要两处一起改**。
3. **改造 `hex_map_view._visible_tiles()`**：判断从「**缺键**」升级为「**缺键或空**」，
   命中就走 `Fatal.fatal("E-MAP-001")`；报完 `return out`（当前帧仍要返回，别让 `_draw` 炸）。

> 用户这条方向还**顺带简化**了：不再需要"只吼一次"的标记 —— 致命路径本身就是"报完就退"，没有第二次。

## 三、自检：`tests/fatal_check.gd` + `.tscn`（13 条全绿）

跑法（**必须用场景跑**，`--script` 不注册 autoload）：

```
godot --headless --path . res://tests/fatal_check.tscn
```

覆盖：有数据不报 / `state = {}` 报 `E-MAP-001` 且 `count=1` / **`{"tiles": {}}`（键在但为空）也报** /
恢复 state 后不再报 / `suppress_quit` 能拦住真退出 / **码表与文档双向同步**。

stderr 里能看到报错本身：

```
ERROR: [致命 E-MAP-001] 地图没有地块数据（state.tiles 缺失或为空）：世界生成没跑成，画面会是空白一片。
```

## 四、范围外

- **不**给项目里其它"静默兜底"逐个接码（`view_world_page.refresh()` 的 `is_instance_valid(map)` 早退、
  `_refresh_unit_panel()` 那类早退……）。本次只把**被问到的那一处**接上、把**机制**立起来；
  以后要收哪些，用户点名即可。
- **不**做 `OS.alert` 之类弹窗（用户要的是"报码 + 结束进程"，先保持简单）。
- **不**自动补救（例如自己补调 `generate`）—— 那与 fail-fast 方向相反。

## 五、长期护栏（这两条不是一次性检查）

- `CODES` 里每个码都要在 `docs/错误代码.md` 出现；
- 文档里出现的 `E-XXX-NNN` 码都要在 `CODES` 里登记。

以后**加码忘了写文档**、或**文档里写了没登记的码**，`fatal_check` 都会红。
