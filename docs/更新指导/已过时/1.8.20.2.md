# 1.8.20.2 · 修 bug：下半屏点已点亮地块，简约信息小窗跑到屏幕外

> 状态：✅ 已完成
> 定位：1.8.20 的第二个补丁段（承接 1.8.20.1 全屏）。

## 一、症状（用户报的）

屏幕**下半屏**左键点**已点亮**的地块 → 简易信息**不显示在鼠标位置** ✗。
对照组：**上半屏**的已点亮地块 ✓ 正常；**整屏的迷雾地块** ✓ 都正常。

## 二、根因

`scripts/ui/views/view_world_page.gd` 的 `_place_tile_info()` 在**同一帧**里"先加内容、再定位"：

1. 容器的"最小尺寸"要到**下一帧**才按新内容算 ✓ —— 所以那一帧量到的还是**旧尺寸** → 夹取（clamp）按"矮"的算 → 小窗被放得很低；
2. 之后 `minimum_size_changed` → `_fit_tile_info_size()` **只改了尺寸、没有重算位置** ✗ → 小窗从那个低位置**向下长** → 长出屏幕。

于是：
- **迷雾格**内容短（一行「（未点亮：迷雾）」）→ 新旧尺寸差不多 → 夹取位置本来就够用 → 看不出来 ✓
- **已点亮格**内容高（势力 / 名称 / 地形 / 土地 / 建筑，可占领时还多一个按钮）→ **下半屏必然溢出** ✗

## 三、改法

1. 新增成员 `_tile_info_gpos` —— 把"这次该贴哪儿"记下来；
2. 把定位抽成 `_apply_tile_info_pos()`：用**记下来的鼠标位置 + 当前尺寸**算；
3. **`_fit_tile_info_size()` 量准尺寸后顺手重算位置** ← 关键的那一刀；
4. 顺便加**上方翻转**：下方放不下就放到鼠标上方。否则夹取的结果会贴着屏幕底、还盖住鼠标。

## 四、验收

- 自检 **15 / 15** ✓
- 截图 **42 → 43 张** ✓
- 新增镜头 `08a2_tile_info_low`：在 `(520, 640)` 点已点亮地块 → 出图确认小窗**整个在屏幕内**，并且**翻到了鼠标上方** ✓✓

## 五、教训（写下来免得再犯）

**"容器尺寸要到下一帧才准"这件事，不只是要补一次尺寸 —— 位置也必须跟着重算。**

上一次修同一个坑（v1.8.2，那时只出现了"小窗高 354 而内容只需 66"）**只补了尺寸** ✗，
于是留下了这次的半个 bug ✓。位置与尺寸是**一对**，补一个就得补另一个。

> 顺带说明为什么这个 bug 只能靠**截图**兜住 ✗：无头自检里视口只有 64 高（见 1.8.20 的备忘），
> 夹取结果会退化成"贴 0"，位置类断言在那种环境下没有意义。
