# v1.8.8 · 世界升格为 root

## 一、目标

把**大世界**从"五个平级页面之一"提升为**游戏底层（root）**；**管理 / 日志 / 世界泡 / 至宝** 变成它上面的**二级浮窗**。

> 依据：绝大多数 4X 游戏的大地图都是 root 级。而且这也贴合本作设定——**世界泡就是舞台本身**，其他系统都是"在这个舞台上打开的窗"。

## 二、设计

- **世界地图常驻**：任何时候都在，不会被"切走"。
- **四个二级窗口**：
  - **日志** = 居中大浮窗（四周留边，**能看见底下的世界**）——这是"浮窗感"的标准样板（v1.8.6 已做）
  - **世界泡 / 至宝** = 大浮窗（尺寸待试玩后定）
  - **管理** 已在 v1.8.7 消失
- **关闭浮窗 = 回到纯地图**（Esc、关闭按钮、或点浮窗外的地图区域——**三选一或都做，试玩定**）。
- **世界地图在浮窗打开时的行为**：建议**压暗但不禁止拖动**（保留"我在世界之上操作"的感觉）；如果实测手感差，再改成阻断。

## 三、涉及文件

- `scripts/ui/game_screen.gd`：从"内容区切换视图"改成"世界常驻 + 浮窗叠加"
- `scripts/ui/view_host.gd`：核心改造——由 `show_view(全屏页)` 变成 `open_panel(浮窗) / close_panel()`
- 各视图的根节点：从"全屏 `Control`"改成"有明确尺寸与位置的浮窗面板"
  - `view_manage_page.gd`（已废，不动）
  - `log_view.gd`、`gacha_view.gd`（世界泡）、`treasure_view.gd`（至宝）

## 四、风险与注意

- **`view_host` 是这次改动的震中。** 它现在负责"缓存视图 + 切换时刷新"（v1.6 修过的那个 bug 就在这儿）。改成浮窗后，**"切回时刷新"这条保证不能丢**——否则会重现"修建后进管理页看到空列表"那类问题。
- **测试影响最大的一段**：截图自检的 36 张图几乎全部会变（视角变成"地图 + 浮窗"）。
- **`_switch_view` 的调用点很多**（各视图互相跳转，如至宝跳世界），改造时要逐个确认。

## 五、验收

1. 任何时候地图都在底层；打开任一浮窗都能看出"世界还在下面"。
2. 关闭浮窗回到纯地图；再从角落按钮打开任一浮窗，**内容是最新的**（不能出现旧缓存）。
3. 视图之间的跳转（如"至宝 → 招募 → 跳到世界选地"）**仍然走得通**。
4. `跑自检.bat` → 12/12。
5. 截图自检 36 张**全量重拍**并逐张确认。

## 完成记录（v1.8.8）

### 结构

```
game_screen
├─ 顶部资源栏
├─ content_host（ViewHost）── 只放**大世界**，常驻，永不切走
├─ dim（压暗层，ColorRect 0.35，mouse_filter = IGNORE）
├─ 悬浮按钮（科技树 / 日志 / 至宝 / 世界泡 / 结束周期）
└─ 二级浮窗（PagePanel：至宝 / 世界泡）+ 工具浮窗（科技树 / 日志）
```

- **`_setup_world()`**：开局就把世界立进 `content_host`，之后不再动它。
- **`_switch_view(id)`** 语义变成开关：`world` → 关掉所有浮窗回纯地图；别的 id → 打开对应浮窗。
- **新增 `scripts/ui/panels/page_panel.gd`（`PagePanel`）**：通用二级浮窗 = 标题栏 + ✕ + 内部页面。至宝 / 世界泡都用它装。

### 两个"必须守住"的点

1. **v1.6 那条"切回时必须刷新"的保证没丢** —— `_open_panel()` 每次打开都会调内部页面的 `refresh()`。
   （指导文件第四节点名警告的就是这条：浮窗化以后如果只做 `visible = true`，就会重现"修建后进来看到空列表"。）
2. **`view_host.gd` 没有拆** —— 指导文件说它是"震中"，要改成 `open_panel/close_panel`；
   但实际 grep 发现 **`treasure_view` 和 `log_view` 各自也用它管子页签**（角色/装备/道具、任务/记录/图鉴/手册）。
   拆掉会连带砸两个内部容器 → **保留原样**，浮窗管理放在 `game_screen` 这一层。
   （指导文件那句"震中"是针对"屏幕只有一个内容区"的旧结构说的，现在已经不是那个结构了。）

### 关闭浮窗的三条路（指导文件说"三选一或都做，试玩定"）

- ✅ **✕ 按钮**
- ✅ **Esc**（优先关浮窗；没有浮窗时才轮到收收支悬浮窗/关对话框）
- ⬜ **点浮窗外**：**没做** —— 因为压暗层设成了 `MOUSE_FILTER_IGNORE`，
  即指导文件更想要的"**压暗但不禁止拖动**"（保留"我在世界之上操作"的手感）。两条路是冲突的，先按后者来。

> 顺带解决了 v1.8.7 留下的那个问题：**"至宝/世界泡 要不要 toggle"** —— 正式答案是**要**，
> 而且现在有了 ✕ 和 Esc，玩家不会再被困在浮窗里。

### 兼容处理（这条让测试改动降到零）

`views[id]` 现在指向**浮窗内部那一页**（`panel.page`）而不是浮窗本身。
于是 `character_page.gd` 里那句 `goto_view("world")`（"至宝 → 跳到世界选地"）、
以及截图自检里所有 `gs.get("views")["treasure"]` + `_switch(sub)` 的写法**全部原样可用**，
只是视觉效果从"整页"变成"地图 + 浮窗"。

### ⚠️ 我自己的一个失误（被守卫拦住了）

`_ready` 里那行 `_switch_view(DEFAULT_VIEW)` 在文件中**出现两次**（还一次在 `_toggle_page`）。
我第一版替换脚本的"恰好匹配 1 次"守卫报了 `!! 匹配 2 次` → 替换**没执行** → **大世界压根没被创建**，
症状是一连串截图 TIMEOUT + `Invalid access to property or key 'world' on a base object of type 'Dictionary'`。
改用更长的上下文锚点（带上 `AppSettings.changed.connect(_refresh)` 那行）后一次通过。

> **值得一提的是：这次是工具里的守卫先报的错，不是测试。**
> 上一段（v1.8.7）我正是因为缺这道守卫才删错了 120 行。**"改之前先确认锚点唯一"应该固化成常规动作。**

### 待定 / 遗留

- **至宝 / 世界泡 的浮窗尺寸**（现 1120×620）—— 指导文件写"待试玩后定"。目前看：**世界只从左边缘露出一条**，"浮窗感"不如日志浮窗（那是有 72px 留边的）。
- **标题重复**：`PagePanel` 的标题 + 页面自己的标题 → 打开至宝会看到两个"至宝"。要不要去掉页面自带的那个，等布局定型一起处理。

### 验证

- 出图确认：至宝浮窗打开时，**左侧能看见地图六边形、上方能看见世界页工具条** —— "世界还在下面"成立 ✓
