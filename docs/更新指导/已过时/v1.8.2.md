# v1.8.2 · 左键语义重做 + 简约地块信息小窗

## 一、目标

**取消"选中地块"这个概念**，改成三档优先级：点领地 → 开据点管理窗口；点单位图标 → 选中单位；点空白 → 在鼠标位置弹"简约地块信息"小窗。

> 背景：原来的做法是"点同一格轮换内容"（市中心 → 各公民 → 地块）。现在地块不再可选中，**单位只能靠点图标来选中**——所以这一段其实是**原"点选逻辑"的扩大版**，且从"可选优化"变成了**必需品**。

## 二、设计

### 左键优先级（高 → 低）

1. **我方领地块** → 打开**据点管理窗口**（v1.8.4 才有窗口；**本段先留一个可后续接上的空入口**）
2. **单位图标** → 选中该单位（`sel_uid`）
3. **空白处** → 在**鼠标位置**弹**简约地块信息**

### 简约地块信息小窗的内容

- 坐标、地形、势力
- **地块明细**（原来在据点面板里的那一块搬到这里）
- 资源点（如有）、建筑数量（如有）

### 要一起处理的两个细节

- **单位重叠**：一格多个单位时图标排成一排，点击按**最近的图标中心**判定（阈值约 `hex_size * 0.22`）；重叠误点时**退回**按顺序轮换（保留旧机制作为兜底）。
- **客人 vs 公民**：`_draw_tile` 画的是**该格所有单位**（含客人），而旧轮换候选**只收公民**。**口径必须一致**：点客人图标时不要静默失败——要么允许选中客人，要么明确忽略并提示。

### 不再做的事

- 不再设置 `selected_key`（黄色选中框消失）。
- `tile_selected` 这个信号**语义变了**（不再是"选中地块"），建议改名为 `tile_clicked` 之类，避免以后误导。

## 八、踩坑记录（2-C 实测）

**"让面板尺寸贴合内容"这件事，量早了会拿到过时值。**

小窗第一次显示时高度是 **354px**，而内容只需要 **66px** —— 底下一大片空白。诊断打印：

```
① 调用刚返回： size=(210,354)  min=(210,354)   ← 此刻"最小尺寸"就是 354
② 1 帧后：      size=(210,354)  min=(210,66)    ← 一帧后它才算对
```

**根因**：容器的 `get_combined_minimum_size()` 要到**下一帧**才会按新加进去的内容重算。
**所以**：自由摆放的面板，光在"当前帧"设一次尺寸是不够的。

**修法**：接住 `minimum_size_changed` 信号，等它真正算好时再把尺寸校一次。
（比"`await` 一帧"更稳，且不把函数变成协程。）

> **通用教训**：**Godot 里"布局"是延迟结算的。**
> 任何"根据内容去算尺寸 / 位置"的代码，都要先问一句：**"我读的这个值，这一帧算好了吗？"**
