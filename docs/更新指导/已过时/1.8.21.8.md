## 三、清单本身要一起改的地方（否则它会继续失真）

1. **头部「怎么产生的」**
   现在写的是 `跑截图.bat` → 逐张对照 → 记录。
   `1.8.21.1` 已把 `跑截图.bat` 恢复，**这句重新成立** —— 但要补上**产物是本轮的**（`tests/_shots/` 每次清空重拍）。
2. **「进度」那行**：现在写「已检查 **16 / 39** 张（2026-10-10）」。
   截图张数变了（恢复后 42±N，且 `1.8.21.1` 补了 `08g2`）→ **重新计数**，
   并改成**按轮次**记：「第 1 轮（2026-10-10）：16 张｜第 2 轮（本轮）：X 张」。
   > 这样以后每轮只在下面追加，不用把上面的数字改来改去（改来改去正是它失真的原因）。
3. **「还没检查的 23 张」** → 本轮**全部过一遍**，逐张给结论，然后**把这一节删掉**（没有"还没检查"就不该留着）。
   注意有几张**名字/内容已经变了**：`02b_dialog_settings` 所在的设置弹窗已拆成四页
   （`02b1/02b2/02b3` 是 `1.8.21.1` 恢复的截图脚本里就带着的）、`12_log_manual` 的标题重复在本轮修掉。
4. **「已确认正常（别重复查）」** → 保留，并把本轮新确认正常的几项**追加**进去。
5. **「补充记录」** → 追加一条本轮记录（日期 + 做了什么 + 顺带修了什么）。

> **边界（重要）**：这份清单的输入是**截图检查产物**（视觉 / 文案 / 排版）。
> 本批次我在读码时发现的 4 条代码健康问题（角色页 `「管理」` 死引用、手册四处死引用、
> `project.godot` 被写坏、`view_manage_page.gd.uid` 孤儿）**属于 `1.8.21.2`，不要塞进这份清单**
