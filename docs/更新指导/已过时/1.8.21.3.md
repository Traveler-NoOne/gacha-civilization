## 一、bug#2：作弊菜单的敌人列表塌成 0 高度

**位置**：`scripts/ui/game_screen.gd` 的 `_open_cheat_menu()`，第 714~747 行。

**现状**（把结构画出来就一目了然）：

```
DialogLayer
└─ sc = UIKit.scroll(v)              ← 外层滚动容器（1.8.20 为修"底部按钮被挤出屏幕"而加）
   └─ v = VBoxContainer
      ├─ 「摧毁敌对单位」标题 / 说明 / 「当前大世界敌对单位：N 个」
      ├─ lsc = UIKit.scroll(list)    ← ✗ 内层滚动容器（问题在这里）
      │  └─ list = VBoxContainer     ← 每个敌人一行：名字 [格key] 战力 + [摧毁]
      ├─ [摧毁全部敌对单位]
      └─ 「关闭作弊：…」
```

**病因**：**滚动容器套滚动容器**。外层 `ScrollContainer` 只给 `v` "最小高度"，
而 `v` 的最小高度由子项的**最小高度**决定；`ScrollContainer` 作为"裁切型控件"，
它自己的最小高度是 **0**（`custom_minimum_size = Vector2(0, 0)` 更是明写了这一点）。
→ 内层 `lsc` 拿到 **0 高** → **一行敌人都显示不出来**。
图 `19_dialog_cheat` 里「当前大世界敌对单位：6 个」下面直接就是 [摧毁全部敌对单位]，
上面那句说明还写着"可以选中大世界中的任何敌对单位直接摧毁" —— 功能等于不可用。

**改法（最小改动）**：**去掉内层 `lsc`，直接 `v.add_child(list)`。**

- 理由：外层 `sc` 已经在滚**整个弹窗**了，内层滚动从一开始就是多余的；删掉之后
  `v` 的最小高度自然把每一行敌人算进去 → 由**外层**滚动条接管，单个 [摧毁] 按钮重新可点。
- **保持外层滚动不动** —— 它是 `1.8.20` 为"底部按钮不要被顶出屏幕"定的，
  理由写在 `game_screen.gd:758-760` 的注释里（那段注释要一并核对：它描述的现象与修法仍然成立，
  但"一定不能给它写死的最小高度"这句现在指的是**外层**，别被误读成"内层也该留着"）。

## 二、配套自检：新增 `tests/cheat_menu_check.tscn`

旧的 `diag_cheat_mouse` 已随 `cdb8cd2` 删除，所以这条**没有护栏**了 —— 补一个同规格的小专项：

| # | 断言 |
| --- | --- |
| 1 | 打开作弊菜单后，敌人列表的行数 **==** `GameState.enemy_tiles().size()`（图里"6 个"就得有 6 行） |
| 2 | 列表的**实际高度 > 0**（直接钉死"塌成 0"这个现象，而不只是看有没有子节点） |
| 3 | 每行的 [摧毁] 按钮 `global_rect` 落在弹窗的**可用区域内** |
| 4 | 点某一行的 [摧毁] → 那个敌人真的从 `enemy_tiles()` 里消失（单个摧毁这条路径真的通） |

> ⚠️ **headless 下不要问真实视口**：视口只有 64 高（`1.8.20-B` 实测）。
> 要问 `DialogLayer.usable_height()` —— 那正是 `1.8.20-B` 为这类断言留的口子。
> 跑法同其它三个：`godot --headless --path . res://tests/cheat_menu_check.tscn`（**必须是场景**，`--script` 不注册 autoload）。

## 三、复查三张存疑图（有图才有结论）

### bug#6 「菜单类弹窗半透明，底下文字透上来」

- **代码证据**：`DialogLayer` 用的是 `UIKit.BG_PANEL` = `Color(0.10, 0.10, 0.145)`，**alpha = 1.0，完全不透明**；
  背后那层 `Color(0, 0, 0, 0.62)` 的 veil 是**有意的**遮罩（`dialog_layer.gd:24`）。
- **所以**：要么 2026-10-10 那天看到的是**别的东西**（例如列表塌陷后露出的空隙 / 半透明的某个子面板），
  要么是此后某次改动顺带修掉了。
- **怎么收**：重拍 `02b_dialog_settings` / `02c_dialog_feedback` →
  ① 若仍能透出底下菜单文字：说明来源另有其人，继续查（**不要**先去调 `BG_PANEL`）；
  ② 若看不透：**结案**，并把结论写成"代码上一直是 BG_PANEL 不透明；2026-10-10 的观感成因未复现"，
  **不要**写成"已修复"（我们并没有改过它）。

### bug#7 「鼠标附近多出一个只写 `0.0` 的小方块」

- **已经查清的部分**：`08e_tile_menu` 里那个带 🔨 的方块 = **右键功能菜单本身**（左边那行小字是**格子名**，
  小字号下逗号看着像点）→ **不是 bug**（清单里已就地记过）。
- `20_unit_panel` 那张已随 **v1.8.20.5**（补回单位条 / 单位操作窗）结案。
- **只剩一张**：`21_recruit_pick`。重拍后确认还有没有那个 `0.0` 方块；有就查它是谁的 Label，
  没有就结案。

### bug#12 「截图清单描述与图不符」

→ 已并入 `1.8.21.1`（重写 `08g` + 补 `08g2`），本段不重复处理。
