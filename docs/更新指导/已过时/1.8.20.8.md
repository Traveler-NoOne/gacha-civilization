# 1.8.20.8 · 随机数种子接上存档：同种子 = 同一条随机数流

> 起因：用户指出 `GameState._ready()` 里无条件 `_rng.randomize()` 会让"读档后不可复现"，
> 提议"新游戏随机化、有存档时把存档里的 seed 放回 `_rng`"。**方向对，位置要挪。**

## 一、先核实的四件事

| 事实 | 位置 |
| --- | --- |
| `_rng` 是**真正干活的那个**随机源 | `game_state.gd:983/985`（客人离去）、`1622/1624/1639`（演变/事件）、`1631`（`WorldGen.evolve`）、`gacha.gd:275/289`（打捞生成资源点/扩建地图） |
| 它**从来没被 `state["seed"]` 播过种** | 全项目只有 `world_gen.gd:33` 用那个种子，而且是它**自己的局部** rng → `_rng` 一直是 `_ready:34` 的时钟随机 |
| 种子**确实存在**存档里 | `new_game()` 的 `"seed": s`（`s` 为 0 时取时钟） |
| 读档**没有恢复它** | `load_from_slot()` 到 `_migrate()` 就结束了 |

**为什么位置要挪**：`_ready` 的 `else` **不是读档**（它也是 `new_game()`）——
真正的读档是玩家从菜单选槽时走的 `load_from_slot()`。所以要播种的地方是**两处**，不是它。

## 二、改动（全在 `scripts/core/game_state.gd`）

1. **`_ready()`**：删掉无条件的 `_rng.randomize()`（种子改由下面两处按状态播，否则会把它覆盖掉）。
2. **`new_game()`**：`s` 定稿后 `_rng.seed = s` → "同一个种子 = 同一局"对赌注/演变/事件/打捞同样成立。
   （传 0 时 `s` 已取时钟种子，所以"每局开新游戏都是新的"没有被破坏。）
3. **`load_from_slot()`**：`_migrate()` 之后 `_rng.seed = int(state.get("seed", 0))` → 读回来的局接上同一条流。

> 附：用户此前已把该函数里"两支都是 `new_game()`"的 `if / else` 削成 `if state.is_empty(): new_game()`，
> 本次**原样保留**该行。

## 三、**边界**（写清楚，免得以后误以为"同种子=全复现"）

| 仍不可复现的 | 为什么 |
| --- | --- |
| **抽卡结果** | 抽取走的是 `gacha_view.gd:28/34` **自己的** `_rng`（`Gacha.draw(..., _rng)`），不是 `GameState._rng` —— 本次按用户决定不动 |
| **「扩建地图」按钮** | `view_world_page.gd:140` 的 `_rng()` 每次 new 一个并 randomize |

本次做到的是：**演变 / 事件 / 客人离去 / 打捞生成 —— 现在可复现**。

> ⚠️ **更正**（1.8.20.9 补）：当时这里写的是"世界生成（本来就可复现）"，其实不准确 ——
> 当时世界生成**与种子完全无关**（`_make_tile` 根本没用那个 rng，地形只由坐标哈希决定，
> 所以每局地图一模一样）。**1.8.20.9 已改成"地形/资源 = f(坐标, 世界种子)"**，从那之后
> "同种子 = 同地图"才真正成立。

## 四、自检

本次**新增的唯一自检文件**：`tests/seed_check.gd`（只覆盖本次改动）。

跑法（项目根目录）：

```
godot --headless --path . --script res://tests/seed_check.gd
```

10 条断言全通过：

- `new_game(20240607)` 后 `_rng.seed` 就是 20240607
- 同种子两局：**世界一致**、**随机数流逐位一致**
- 换种子 → `_rng.seed` 跟着换、第一个随机数不同
- 不传种子 → 取时钟种子、且与 `state["seed"]` 一致
- 存档 → 搅乱 `_rng` → 读档 → 种子**恢复**成本局种子（用完把 0 号测试槽删掉）
