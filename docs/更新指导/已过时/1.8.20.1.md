# 1.8.20.1 · 画面设置加「全屏」勾选框

> 状态：✅ 已完成
> 定位：**1.8.20（实装分辨率系统）的补丁段** —— 版本号由用户定为 1.8.20.1。
> 模式：教练模式（用户动手，助理出指令 + 复验 + 收尾文档）。

## 一、需求

画面设置里加「全屏」设置项，形式为**勾选框**。

## 二、做了什么

- `scripts/core/app_settings.gd`：新增 `_fullscreen` 与 `fullscreen()` / `set_fullscreen()`，
  和分辨率一起落进 `user://settings.cfg` 的 `[display]`。
- `scripts/ui/menu_screen.gd`：画面设置页在「帧率限制」下面加 `UIKit.toggle_checkbox("全屏", …)`；
  **勾一下立即生效**（全屏不涉及 UI 重建 → 按 1.8.20 定下的规则"不涉及 UI 重建的直接生效"）；
  **退出全屏时还原窗口尺寸并重新锁边**，否则会留一个没锁的窗口。
- `scripts/ui/main.gd`：启动时若存的是全屏 → `WINDOW_MODE_FULLSCREEN`，并且**跳过**设窗口尺寸与锁边
  （全屏以屏幕分辨率为准）。
- 用 `WINDOW_MODE_FULLSCREEN`（无边框全屏）而不是 `…_EXCLUSIVE_…`：Alt-Tab 切换更自然、不会黑屏闪一下。

## 三、一个值得记的设计澄清：全屏与分辨率**不冲突**

用户在指导过程中提出：*"更改全屏和更改分辨率不冲突吧，我看过好多游戏也支持全屏低分辨率来着。"*
—— **用户是对的**，我原本建议的"全屏时禁用分辨率下拉"被撤回。

因为在本作里，「分辨率」其实**兼任两件事**：

| 身份 | 什么时候生效 |
| --- | --- |
| ① 窗口尺寸 | 仅**窗口模式**下有意义 |
| ② **UI 缩放档**（1.0 / 1.25 / 1.5） | **全屏时照样生效** |

所以「全屏 + 1280×720 档」＝ **全屏，但 UI 按 100% 排版**（信息量大、字小）—— 正是玩家说的"全屏低分辨率"的手感；
「全屏 + 1920×1080 档」＝ 全屏 + UI 1.5 倍（大 UI）。

→ 因此**没有做**"全屏时禁用分辨率下拉"（那等于白扔掉一个有用的设置）。
→ 也**没有**改下拉标签（用户决定不做）。

### 一条诚实的边界

真正意义上"**低分辨率渲染再放大**"（画面糊一点、但省性能）本作**做不到**：
B-3 阶段关掉了自动拉伸（`stretch=disabled`），换来的正是"按真实像素排版、不糊"。

→ 现状是：**全屏 = 以屏幕原生分辨率渲染 + 按所选档缩放 UI**（UI 尺寸会变，画面不糊）。
→ 哪天真想要那种手感，需要单独开一段重新引入渲染缩放，代价是会把 B-3 的工作抵掉一部分。
