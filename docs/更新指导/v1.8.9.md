# v1.8.9 · 加载界面

## 一、目标

做一个**过场加载界面**：**新游戏**和**读取存档**都先经过它。

## 二、设计

```
┌──────────────────────────────────────────────┐
│                                              │
│              抽卡文明（标题 / 立绘）             │
│                                              │
│  tips：…                                      │
│  ■■■■■■■■□□□□  ← 进度条                      │
└──────────────────────────────────────────────┘
        左下角 = tips          右下角 = 进度条
```

- **右下角：进度条**
- **左下角：tips**（至少准备 3~5 条，随机取一条；例如世界泡/量子之海的设定、操作提示）

## 三、必须处理的一件事：**别让它一闪而过**

Godot 加载这个体量的 2D 游戏**几乎是瞬间的**。如果照实做，加载界面会**闪一下就没**，等于没做。

**处理方式（二选一）**：

| 方案 | 说明 |
| --- | --- |
| **保底显示时间**（建议） | 不管加载多快，**至少显示 1.0~1.5 秒**；进度条按这个时间平滑推进 |
| 真异步加载 | 用 `ResourceLoader.load_threaded_request` 取真实进度；**仍建议再加一层最短时间** |

> **本段的"进度条"本质上是"仪式感"，不是性能需要**——这一点要在实现里写清楚注释，免得以后有人以为是真实进度。

## 四、涉及文件

- **新增** `scenes/loading.tscn` + `scripts/ui/loading_screen.gd`
- `scripts/ui/menu_screen.gd`（新游戏 / 读取存档 → 先切到加载界面）
- 主场景流程（`scenes/main.tscn`）——决定"谁来启动加载界面"

## 五、测试影响（要一起处理）

- **截图自检**从主场景启动 → 会先撞上加载界面。要么在测试里跳过它，要么等它跑完再开始拍。
- **headless 自检**多数直接构造 UI，不受影响；但 `diag_v12`（存档版本校验）会碰到"读取存档"的流程，需要确认它不依赖加载界面。

## 六、验收

1. 新游戏 → 出现加载界面 → 进度条走满 → 进入游戏（**不会一闪而过**）。
2. 读取存档 → 同样经过加载界面。
3. tips 每次（或每几次）会换一条。
4. `跑自检.bat` → 12/12；截图自检 36 张正常。
5. 试玩确认：加载界面停留时长**不觉得拖沓**（这是本段唯一需要手感的部分）。
