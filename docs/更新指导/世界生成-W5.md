# 世界生成 · W5 —— 裁切器与采样转换（S6 + S7）

> 状态：⬜ 未开始（用户将统一审阅）
> 依赖：W4
> 总纲：[世界生成-过程模拟.md](./世界生成-过程模拟.md)（第五节 S6/S7 与 5.4、第七节）

## 一、目标

把"**一张大死地图**"变成"**一块半径 21 的六边形地块图**"：
先按条件**裁一块六边形区域**，再把这块区域**采样转换成地块**。

## 二、做什么

### 2.1 S6 裁切（第七节）

| 层 | 内容 |
| --- | --- |
| 用户口径 | **海陆比 25%~75% 都算合格**（很松，只是"别太离谱"，不是门槛） |
| 第 1 层：淘汰 | 全海 / 全陆、海陆比超出 25%~75%、**窗口超出图边**（中心必须留足边距） |
| 第 2 层：排序 | 在合格的里按 **`|海 − 陆|`** 取最接近 50:50 的 |
| 第 3 层：形态（W6 时再加） | **群岛 vs 大陆**：陆地**连通块数** + **最大块占比** + **海岸线曲折度** |
| 实现 | **滑窗扫描**（粗到细：先在粗网格上扫候选，再在最优附近细调），窗口为**六边形** |

### 2.2 S7 采样转换（总纲 5.4）

| 项 | 规则 |
| --- | --- |
| **高程** | 格内**面积平均**（**不要只取中心点** —— 否则地形规则化、海岸线像尺子画的） |
| **海 / 陆** | 格内**水域占比 > 50%** 才算水 → 海岸线自然、小岛留得住；再加"**小于 X 平方像素的孤岛丢弃**"防噪声碎岛 |
| **地形 / 地物** | 按 `biome` + 高程**查表**（喂给现有 `terrain` / `cover` 两层） |
| **资源** | 沿用"木头←森林、煤/铜←山丘"的**按地貌**做法（不额外引入随机） |
| **河流 / 湖泊** | 按 W4 的规则产出 `state["edges"]` |

## 三、验收

1. **裁出来的图合格**：海陆比落在 25%~75% 内，且是**合格窗口里最接近 50:50** 的；
   把这个比例与窗口位置**打印出来**（便于人工核对与调参）。
2. **能真的显示**：半径 21 的六边形地块图能被现有渲染（`hex_map_view`）正确画出，
   海岸线自然、没有"锯齿状的大方块"。
3. **同种子 + 同裁切窗口 → 逐位一致**；4 个无头自检全绿。
4. **人看**：这张图**像一张地图**（有海岸线曲折、有岛、有海）。

## 四、范围外

- **不做玩家可选**（群岛/大陆、卡池组、质量档都在 W6）。
- **不做拼接**（W7）。
- **不为"好看"去调高程阈值** —— 只允许为了"更像真实地理"而调（总规则第 8 条）。

## 五、风险

- **采样规则是"观感"的关键**：面积平均 vs 中心采样、水陆的 50% 阈值、孤岛阈值 ——
  这三样都会明显改变海岸线长相。助理会**各出一版图**给用户挑（这属于可逆参数）。
- 裁切窗口是**六边形**，要小心"窗口落到图外"的边界情况（第 1 层已含淘汰规则）。

### 一个**试过又改回来**的设计（重要，别重复踩）

> "裁到极地 = 寒带世界"这个玩法**将来若要做，应当另加一个"纬度偏移"选项**，别动默认。

（另外试过把 `PRECIP_MM_PER_RAW` 放大一倍去压沙漠占比 → **一格都没少**（572→572），

# ★ 剧情依据（2026-10-13 用户口述，**这段决定了裁切的默认行为**）

> 用户原话（要点）：*"开头的地图原型可以是冷暖俱全的，但是裁切下来的地图可以不是冷暖俱全的，
> 因为一个剧情设定：原本是完整的地球和前文明，但是等到**华从冷冻仓出来后，只剩下残破的世界了**，
> 飘零在量子之海中，因此游戏开始时的世界不完整、不是冷暖俱全是很合理的，**本来就是大部分土地都失去了**。
> 在剧情设定安排上，还可以让**世界地形参数图是原本的完整的地球**，而游戏地球就是原本地球的部分之一，
> 其他都在**坠入量子之海时和之后丢失了**。直到华苏醒，以及其他助手的苏醒，**稳定了这个世界泡**。"*

## 由此定下的三条设计（**不是缺陷，是设定**）

1. **死地图 = 原本的完整地球**（冷暖俱全、气候完整）——它就是"原型"，也是 `DEAD_SCALE` 那张大图的**叙事身份**。
2. **游戏里的世界 = 原本地球的一块碎片**（裁切窗口扣下来的那一块）→
   **"这块世界不冷暖俱全"是合理的**：裁到高纬就是寒带碎片、裁到赤道就是热带碎片。
3. **大部分土地已经丢了**（坠入量子之海时+之后）→ 世界在地图上"不完整、边缘残缺"是对的，
   而不是"生成失败"。

> 顺带给了 W7 一个顺理成章的说法：**拼接新世界 = 找回 / 拼回丢失的碎片**
> （华与其他助手苏醒、稳定这个世界泡的过程）。

## 实现（已按此改回并验证）

- **纬度按"死地图（原本地球）"的绝对纬度算**，**不减去裁切偏移** ——
  否则裁到北边的世界仍以赤道为中心（我踩过：换窗口温度只差 0.19℃）。
- 实测：窗口 (0,0) → 降水 0.441／**9.74℃**（温带碎片）；
  窗口 (18,18) → 降水 **0.063**／**−9.05℃**（**裁向北 = 又冷又干的碎片** ✓ 正是设定要的）；
  **切回 (0,0) 逐位一致** ✓。
- 世界内部的温差天生较小（**21.3℃**，而"冷暖俱全"时是 34.5℃）——**这正是"碎片"该有的样子**，
  所以自检里那条断言按死地图尺度分桶、阈值放宽到 12℃。

### 附带查实的一条（**不是 bug**）

沙漠占比偏高（BW 572 格）**不是**毫米标尺的问题（放大一倍→一格没少），
也**不该**靠调大 `RAIN_BASE` 去压：**内陆干是物理上对的**（大陆内部本来就是沙漠带，
现实里的戈壁/撒哈拉就是"离海远"的结果）。所以 `RAIN_BASE` 已**退回 0.008**。
→ 若将来觉得沙漠太多，旋钮是 `RAIN_BASE` 或柯本的干旱阈值，**但那属于调口味，不是修 bug**。

### ⚠️ 由此解决的一个成本矛盾（**重要设计**）

原来"网格分辨率跟着比例一起放大"（128 → 192 …）→ 提到 4 倍就成了 **512²**，
建场要十几秒。**关键洞察：地形是纯函数（任何坐标都能直接算），只有降水必须用栅格。**
→ 把两者**解耦**：

| 常量 | 管什么 | 值 |
| --- | --- | --- |
| `DEAD_SCALE` | **原型世界多大**（= 比例） | **4.0** |
| `FIELD_GRID` | **气候栅格分辨率 = 生成耗时的唯一旋钮** | **160** |

代价（已记档）：死地图越大，**气候在游戏地图里的采样越粗**（每格覆盖更大范围）；
将来 W6 可以把它做成"气候质量档"。

实测：**建场 2814 ms**（160×160×12 = 307,200 格·月）；世界只占死地图 **±1/4 的纬度** →
默认窗口下是一块**偏热的碎片**（年均 6.7 ~ 27.7℃），世界内温差 4.8℃ —— **正是"碎片"该有的样子**。

## 降水问题的诊断（2026-10-13）：**先归因、再动手**（采纳第三方评审的意见）

用户找另一个 AI 评审了我的降水诊断。**它有几条说对了，我有两处确实错了**，逐条记：

### 我错的两处

1. **"常数偏大 5~7 倍"不严谨** → **撤回**。15688 vs 地球最湿（年 ~11800）只大 1.3 倍；2317 vs 广州 1800 大 1.29 倍；
   拿"北京 570"当参照才是 4 倍 —— **换个参照就换个倍数**，这种结论没有意义。
2. **更严重：我那个对比根本不成立**。我拿"窗口 (0,0) vs (18,18) 的同一个**世界格**"比较 ——
   但那**根本是两个不同的物理位置**（换窗口后，同一世界格对应原型图上另一处）。
   **"不同地方降水不同"是天经地义，什么都证明不了。** 这是**方法论错误**。
   → 它要求的实验（**固定同一物理坐标**，跨分辨率、跨窗口）才是唯一能分辨
   "标定错" 还是 "尺度依赖" 的做法。**已照做，见下。**

### 它对、而且最有价值的一条

**"根子在于降水计算没有按物理 dx 归一化，而是按格数累积。"** —— 正确，是真 bug：
我的降水是"**每经过一个栅格**下掉多少"，而不是"**每公里**下掉多少" →
**栅格越密，同样物理距离上就下了越多次雨**。我把栅格 128→384 时数值飞掉，根子在此。
→ 所以它说的顺序对：**先别动常数**（常数现在是补丁，一改分辨率就要重调，无法归因）。

### 它说反的一条（有代码为证）

它说"柯本需要月降水+月均温，不能用年降水"——**但我本来就是按月判的**（`climate.gd` 的 `koppen_at`）：
E 用**最热月**温、A 用**最冷月**温、**Af 用最干月降水**（`driest_month_mm`）、s/w 用 7 月 vs 1 月降水；
**只有 B 类干旱阈值用年降水**，而**柯本标准式本来就如此**（`20·T + 140`）。
→ 这条是"对一个它没看到的实现做的假设"。

### 它的另外两点我的取舍

- **"先把最湿压到 3000mm 是设计目标、不是物理校准"**：道理对；但本项目用户已定
  "**不是硬核游戏、降水不用严谨**"，所以**不做**它建议的"物理量纲重写"（通量散度/蒸发凝结按 dx 积分）——
  对这个游戏是过度工程。**但取其最小版本**：把"每格下多少"改成"**每公里下多少**"，
  一次改动换永久尺度无关。
- **归一化**：它提的"**软钳（sigmoid）代替硬 `min(1.0,x)`** + 参考取**游戏地图范围**"——
  **我完全同意，比我的方案好**（硬钳会把 15% 的格子直接压平）。

### 已做的实验（尺度不变性）—— **结论：还不能下结论（我自己的实验有缺陷）**

固定**原型图上的同一物理点**、同一月，跨栅格 128/192/384 打印 raw 降水：

```
栅格 128：0.00623（crop 0）／ 0.00533（crop 24,12）→ 0.86 倍
栅格 192：0.00517（crop 0）／ 0.01323（crop 24,12）→ 2.56 倍
栅格 384：0.00421（crop 0）／ 0.00704（crop 24,12）→ 1.67 倍
跨分辨率 raw 最大/最小 = 1.48 倍
```

⚠️ **但这个实验自己被"六边形取整"污染了**：`precip_at()` 收的是**六边形坐标**，
我传"世界像素 − 裁切偏移"时，`pixel→hex` 会把位置**取整到格心**，两个窗口下落到了不同的格 →
**"同一物理点"其实没落在同一点**。所以：
- 那三行的 0.86/2.56/1.67 倍**不能**用来证明"窗口依赖"；
- 跨分辨率的 **1.48 倍**也**掺了假**。

**下一步（修实验，再下结论）**：新增 `precip_at_pixel()`（按像素采样，不经过六边形取整），
重跑同一个实验；**若同一物理点在两个窗口下仍不相等，那才是真问题**（说明降水场不是原型图的固有属性，
而是"相对于窗口算出来的"）——那时要先修这个，再谈尺度与标定。

同一物理点在两个窗口下**逐位相同（1.000 倍）** → 降水场**确实是原型图的固有属性**，
不是"相对于窗口算出来的"。**没有"窗口依赖"这个 bug**（上一轮的 0.86/2.56/1.67 全是取整造成的）。

#### 结论 2：**尺度依赖是真的，2.18 倍** ✗

128 → 0.00562、192 → 0.00900、384 → 0.00413：**换分辨率，同一物理点的降水就变**，
而且**不是单调**（192 反而最高）—— 因为"每格下多少"与"每格落在什么地形上"耦合在一起。
→ 证实评审那条："**按格数累积而不是按物理距离**"。

#### 结论 3：**毫米标尺偏大一个数量级**（这次是干净的证据）

同一物理点的年降水 = **26039 ~ 56916 mm**（地球最湿约 11800）。
→ 这个点偏湿是一回事，但**两万六到五万七这个量级**说明 `PRECIP_MM_PER_RAW` 大约**大了 10 倍左右**。
（精确倍数**必须等尺度修好之后再定** —— 否则量的是一个会随分辨率漂移的数。）
