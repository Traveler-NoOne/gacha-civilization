## 五、验收规则（每段都要满足）

1. **每段结束必须是"游戏完整可玩"**（总规则第 1 条）——不允许出现"暂时没法建造 / 没法征兵"的中间态。
2. **三个无头自检全绿**（`seed_check` / `fatal_check` / `popup_measure_check`），
   结构变了就**改测试的预期**，不是把红着的往下带（总规则第 2 条）。
   > 「全绿」的项数**只按 `tests/` 下实际存在的算**，不再引用 `15/15` 这个已经不成立的数字。
3. **视觉类改动走容差像素对比**：同状态新图 vs 基线图，平均绝对差（MAD）**阈值 2%**；
   **不许用哈希相等**（渲染不是字节级确定的，连拍两次就有 15/42 张哈希不同）。
   **例外**：`17_dialog_draw`（抽卡结果弹窗自带随机，≈5%）。
4. **观感 / 手感交给用户手测**（既有规矩：脚本能判的用脚本，观感只能人看）。
5. **每段一次提交**（总规则第 3 条），信息形如 `1.8.21.2 死引用清一遍（据点窗口/手册/角色页 + project.godot 修复）`。

## 六、风险与注意

- **截图自检是非 headless 的**，而 README 早记过这个坑：反复起停图形窗口时 N 卡驱动偶发让窗口**卡在灰屏**。
  → 原样保留 **120 秒看门狗**；跑之前先关掉正在开的游戏。
- **恢复来的截图脚本是"旧时代"的**（它上次运行在 2026-10-11，之后发生了 v1.8.20.4 悬停语义、v1.8.20.5 单位窗、
  v1.8.20.11、v1.8.21 地形/地物/河流等一连串变化）→ **先原样跑一遍看它挂在哪**，再逐处适配，
  不要一上来就大改（那样分不清"恢复得不对"和"适配得不对"）。
- **`project.godot` 只许精确编辑**，改完**立刻 `git diff` 核对**（2026-10-11 就是整块替换把两行真设置连同注释写坏的）。
- **不要顺手改地图生成 / 分辨率代码**：那两块刚稳定下来，且都有纯函数约束与自检在守。
- **别把"清理"做成了"重构"**：本批次的目标是**让文档与代码重新对齐**，不是让代码更好看。
