
## 一、总规则（每一段都必须遵守）

1. **每段结束必须是"游戏完整可玩"的状态。** 功能搬家时，**先把新家做好、再把旧入口删掉**；不允许出现"玩家暂时没法建造/没法征兵"的中间态。
2. **自检按需跑：用户要求时跑。** 跑时必须全绿（当前 **4 项**：`seed_check` / `fatal_check` / `popup_measure_check` / `dead_ref_check`）。
   **约 5 个版本以前的旧自检，直接清理掉、不要去改** —— 早期状态变化太大，改旧内容不如重新写。
   > **按需 + 低频**，不必每段都停下来等自检。
3. **每段结束提交一次 git**，提交信息形如 `v1.8.3 政事系统（数据 + 队列 + 征兵）`。
4. **改完就清死代码。** 删掉的入口/控件，其代码与美术一并处理，不留孤儿。
5. **每段的"验收"必须包含你自己的试玩确认**（不只自检绿）。
6. **「点哪弹哪」的浮窗，一律用 `UIKit.place_popup_at(p, gpos)`。** 不要自己写 position + 夹取 ——
   它一次处理完三件事：全局坐标（用 position 会在父节点原点不为 0 时整体偏掉）、
   尺寸要到下一帧才算准（会从旧位置向下长出屏幕）、下方放不下翻到点的上方。
   目前左键简约小窗、右键功能菜单都走它；以后再加任何"贴点弹出"的东西，也用这个。
   > **测试里凡是靠悬停弹出的镜头，必须先 `Input.warp_mouse(点)`** —— 截图是真窗口跑的，

7. **注释写短：代码里只留"为什么不能那样写"（尤其反直觉的坑），来龙去脉写进 commit 信息。**
   > 1.8.20.10 由用户提出：注释太长会把代码淹掉，而"当初为什么要这么改"的价值在**历史**里
   > （`git log` / 更新指导段文件里都能查），不在一行代码旁边。

8. **地图按真实地理过程形成；参数只按"真实感"设，不为平衡而调。**
   玩法上的平衡，将来用**更多样的建筑 / 内容**去弥补（用户 2026-10 定的原则：本作要"更真实"而不是"更好玩"）。
   > 推论：地形/地貌的实现优先抄**真实过程**（噪声场、水流侵蚀…），阈值与系数只允许为了"像真的"而改；
   > 不要因为"海太多/山太少"这类**玩法**理由去调它。

## 二、设计总表（所有段落共享，改动请先改这里）

### 屏幕上的元素与位置

| 元素 | 位置 | 形态 | 说明 |
| --- | --- | --- | --- |
| **大世界（root）** | 铺满全屏 | 地图 + 拖动/缩放 | 六边形地图 |
| **结束周期** | **右下角** | 文字按钮 | 结束当前回合，结算产出，触发下回合事件 |
| **世界泡** | **左下角** | 文字按钮 | 进入抽卡系统 |
| **至宝** | **左下角**，与世界泡相邻 | 文字按钮 | 管理大部分单位，物品。 |
| **科技树** | **左上角** | 文字/图标按钮 → 独立浮窗 | 可研究科技，解锁大部分内容。 |
| **日志** | **右上角** | **书本图标** image 按钮 → **居中大浮窗**，四周留边露出地图 | 任务与引导系统。 |
| **据点管理窗口** | 右侧 | 浮窗 | 用于管理一座城市的人力和政务。 |
| **修建浮窗** | **鼠标位置** | **中型**浮窗 | 用于修建新建筑。 |
| **简约地块信息** | **鼠标位置** | 小窗（跟随鼠标弹出） | 用于查看地块的简约信息。 |

### 左键点击优先级（高 → 低）

| 序 | 点到什么 | 结果 |
| --- | --- | --- |
| 1 | **我方领地**（据点地块） | 打开右侧**据点管理窗口** |
| 2 | 地块上的**单位图标** | 选中那个单位 |

> **右键**：在地块上弹出**球形图标按钮菜单**（目前只有 🔨 = 修建建筑）。

### 术语

- **跑条**：进度条。**政事队列** = 每周期把**行政点数**积累进去，条满即完成（与现有规划队列同一手感）。
- **政事**：可以排队的"据点级事务"。**征兵是第一条政事**。
