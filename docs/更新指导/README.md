> v1.8 是**大世界（世界系统）的整体重写**：把世界升格为游戏底层（root），其余系统变成它上面的浮窗；同时重做地图绘制、点击语义、据点/建筑/科技/日志的入口，并加一个加载界面。

> **本目录的每一份 `v1.8.x.md` 就是一段可独立完成、可独立验收的工作。** 设计决定全部记在这里，**不依赖对话上下文**——所以任何一段都能隔很久之后再捡起来做。

## 一、总规则（每一段都必须遵守）

1. **每段结束必须是"游戏完整可玩"的状态。** 功能搬家时，**先把新家做好、再把旧入口删掉**；不允许出现"玩家暂时没法建造/没法征兵"的中间态。
2. **自检按需跑：用户要求时跑，或累计 7~8 个版本跑一次。** 跑时必须全绿（当前 **15/15**）；结构变了导致测试失效时，**改测试的预期**（不是把红着的往下带）。
   > 2026-10 用户改的规矩：以前是"每段都要跑 `跑自检.bat`"，改为**按需 + 低频**，不必每段都停下来等自检。
3. **每段结束提交一次 git**，提交信息形如 `v1.8.3 政事系统（数据 + 队列 + 征兵）`。
4. **改完就清死代码。** 删掉的入口/控件，其代码与美术一并处理，不留孤儿。
   > **清死代码的方法**：① 先**全项目** grep（**含 `tests/` 与 `selfcheck_runner.gd` 的清单**，这两个地方最容易漏）；
   > ② 删完**必须跑一遍自检** —— 平时那步"重扫语法"用的是 `--import`，它**不解析 `tests/` 下的脚本**，
   > 只有跑测试才抓得到"引用已删东西"的解析错（1.8.20.6 踩过：`mgr2` 在后面一节还在用）。
5. **每段的"验收"必须包含你自己的试玩确认**（不只自检绿）。
6. **「点哪弹哪」的浮窗，一律用 `UIKit.place_popup_at(p, gpos)`。** 不要自己写 position + 夹取 ——
   它一次处理完三件事：全局坐标（用 position 会在父节点原点不为 0 时整体偏掉）、
   尺寸要到下一帧才算准（会从旧位置向下长出屏幕）、下方放不下翻到点的上方。
   目前左键简约小窗、右键功能菜单都走它；以后再加任何"贴点弹出"的东西，也用这个。
   > **测试里凡是靠悬停弹出的镜头，必须先 `Input.warp_mouse(点)`** —— 截图是真窗口跑的，
   > 鼠标若在窗外会触发一次"移出地图"的悬停把弹窗收掉（v1.8.20.4 踩过）。
   > 第 2 条的补充：截图脚本 `_shoot()` 会**等到补间动画结束再拍**（v1.8.20.3 起），
   > 所以"连拍两遍应当一致、改动前后逐张比"是可信的。唯一例外是随机抽卡那张（17_dialog_draw）。

7. **注释写短：代码里只留"为什么不能那样写"（尤其反直觉的坑），来龙去脉写进 commit 信息。**
   > 1.8.20.10 由用户提出：注释太长会把代码淹掉，而"当初为什么要这么改"的价值在**历史**里
   > （`git log` / 更新指导段文件里都能查），不在一行代码旁边。

### 术语

- **跑条**：进度条。**政事队列** = 每周期把**行政点数**积累进去，条满即完成（与现有规划队列同一手感）。
- **政事**：可以排队的"据点级事务"。**征兵是第一条政事**。

## 四、为什么是这个顺序

- **绘制（1）最前**：独立，且修掉现存 bug；世界升格后它是最底层的代码，先弄干净。
- **政事（3）在窗口（4）之前**：窗口下半段要显示政事队列，得先有政事。
- **布局（7）在功能搬家（3~6）之后**：删入口前，功能必须都有新家。
- **世界升格（8）在布局稳定之后**：它动的是"谁在底层"这件事，前面的浮窗都定型了才不返工。
- **加载界面（9）最后**：它要"包"住最终流程，流程没定就包不住。
