## 关键实现

- **分类**：抽象 = 生产力 / 科研点 / 行政点数 / 秩序结晶 / 凝聚力 / 人力；具体 = 食物 / 摩拉 / 木材 / 煤 / 铜 / 铁 / 原油 / 硝石 / 水晶碎屑。
- **存储上限**：`GameState.storage_cap(key)`（-1 = 无上限）；`add_res` 统一夹取；`end_cycle` 生产力盈余先预夹再写溢出日志；`_migrate` 读旧档后按上限夹一次。
- **经典仓储**：`building_db.gd` 新增，`GameState.warehouse_bonus()` 汇总其等级。
- 版本号 `Consts.DEMO_VERSION` → v1.4。

## 附：原始需求（`抽卡文明 更新指导v1.4.docx` 正文，原文照录）

管理系统的中控区中的指挥系统作用不大，扩张的话一般会倾向于世界中选择地块进行占领，此处点击后没有选择面板，而且也不适合，因此此功能意义不大，可删除。
查看可占领地块功能意义不大，而且不能直观感受地块位置来决策，世界系统中可以更直观的查看并进行操作，因此此功能也意义不大，可删除。
派兵清剿的自动性太高，玩家没法一一直观对比决策敌我单位差距，因此意义不大，也可以删除，那么指挥系统就没啥用了。整个都是可以删除的。
同时因为建筑系统大改的缘故，人力系统忘记兼容了，导致现在没法调控人类，于是据点详情里，我们需要在这里重新加入据点人力管理系统，ui姑且先放在据点详情中规划队列的左边。
只显示已修建的建筑，并可以对其进行人力投入。

同时对可用土地的Ui显示逻辑做修改。原本是1.0/1.0，前一个1.0表示可用土地，后一个1.0表示土地上限，不够直观，玩家有误判风险。
需要使用后，例如经典田地，占地0.4后变成0.6/1.0。才能推测出，前一个数字是剩余土地。
因此建议将前一个数字的逻辑从剩余土地改成已使用的土地，默认状态下为0.0/1.0，玩家一开始就能感受到，前者是我还没建造建筑，后者是我最多造多少。

然后是顶部资源栏已经有的资源，食物，生产力，摩拉，科研点，秩序结晶，凝聚力，行政点数，木材，人力等资源。
此处要将抽象资源和具体资源分类，例如科研点，生产力，行政点数之类的划分为抽象资源，木材，食材，摩拉之类的为具体资源。
抽象资源左对齐做俩行，具体资源右对齐做两行。大体上将两者分开。
并且具体资源要显示所有的基础资源，哪怕为0，例如煤炭，铜。
同时抽象资源中，生产力和科研点都要存在上限，并且在实时数据的右侧显示上限，例如生产力为0时应该显示0 / 20，生产力盈余10时，显示10 / 20。
包括之后存在上限的资源。
具体资源除摩拉外都存在存储上限，默认每项资源的上限为100，并新增建筑，经典仓储，可以增加资源存储上限。数值平衡你看着来。
