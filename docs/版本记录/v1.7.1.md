## 一、立绘重新裁剪（用户手裁）

**旧裁剪为什么难看**（根因，值得记住）：取景框 **160×222 是竖长的**，而目标 **190×170 是横宽的**。比例不一致时程序只能裁掉一边，按 35% 偏移一裁，正好切掉最上面 28 像素 —— **蝴蝶发饰和头顶没了，剩下大半是头发**。

> **规则：取景框的长宽比要和目标尺寸一致**，这样"框里看到的 = 最终出来的"，不用赌偏移。

改为**用户用裁图软件手裁**（助手那套脚本切片思路作废，`重新导出立绘.bat` 已删）：

| 用途 | 文件 | 尺寸 | 长宽比 |
| --- | --- | --- | --- |
| 角色页大立绘 | `art/units/grieso/portrait.png` | 190×170 | 190:170 |
| 单位操作窗 | `art/units/grieso/icon.png` | 60×60 | 1:1 |
| 底部单位条 | `art/units/grieso/chip.png` | 28×28 | 1:1 |

**两次被排除的做法**（记下来免得重踩）：
- **抠背景**：用"局部相似度"洪水填充 → 抗锯齿渐变成了"每步只差一点"的通道，**误删 98.3%**。要抠就得"先按背景色全局阈值，再在二值掩码上从边界连通"。
- **留边（letterbox）**：190×170 是 1.12:1、原图 1:1，留边会在深蓝条旁补出**可见的奶油竖边**；且原图四角像素 alpha=3（近全透明），采到的底色是垃圾值。正解是**按目标比例裁切**。

原图 `257×257` **只能缩不能放**；将来做更大立绘需从矢量源重导。母版存于 `art/units/grieso/_源图.png`。

## 二、底栏改造（③）

**布局：左 / 中 / 右 三段式**

```
┌──────────────────────────────────────────────────────────────┐
│ [结束周期]                 (🔵世界球)           [管理][至宝][世界泡][日志] │
└──────────────────────────────────────────────────────────────┘
                            ↑ 整条栏的几何正中
```

- **左侧**「结束周期」`100×40`（原 210×40，并去掉 ▶）
- **正中**球形「世界」按钮 `64×64`，美术图 `art/ui/world-ball-s.png`
- **右侧**四个视图按钮 `96×40`

**"正中间"的做法**（这是本版唯一的新概念）：把底栏切成三段，**左右两区都设 `SIZE_EXPAND_FILL`** → 两区宽度必然相等 → 夹在中间那格**必然是整条栏的几何中心**。不用算像素。

**高亮刷新改成"配对式"**：原来 `_refresh_nav()` 靠按钮**在栏里的顺序**去 `VIEWS` 对号入座 —— 世界球一旦搬到栏外（顺序变了）就会整体错位。改成 `nav_buttons: Dictionary`（视图 id → 按钮）直接索引。

**选中态**：世界球**只调图标明暗**（选中全亮 / 未选中 ×0.78），**不能走 `style_button()`**（那是给矩形按钮的样式盒，会把球形底盖成方块）。
> 注：**图标色是相乘的**，只能"调暗"，做不到比原图更亮 —— 所谓"选中变亮"实际是把"未选中调暗"反衬出来的。（用户自己指出并写进了注释）

## 三、`Art` 抽象（用户引入的重构，本版最漂亮的一处）

新增 `enum Art {UI, ICON}` + 路径映射表 + **按类型分缓存** + 统一入口：

```gdscript
const ART_DIR := "res://art/"
enum Art {UI, ICON}
const ART_DIRS := { Art.UI: "ui", Art.ICON: "icons" }
static func get_icon(name: String, type: Art) -> Texture2D   # 缺图打日志并返回 null
```

然后**回头把两条旧加载路径一起并了进来**：
- `hex_map_view.gd`（地图资源图标）
- `game_screen.gd`（顶部资源栏图标）

最后**删除旧函数 `res_icon()`**（全项目零引用）。

> 这是"单一来源"的标准动作：**先建新路 → 迁移所有调用方 → 再删旧路**，一步不漏。原先 `art/icons/` 与新增的 `art/ui/` 各有一套加载函数，现在只有一条。

**`image_button(name, tooltip, w, h)`**：整颗按钮显示一张图，按钮底用 `StyleBoxEmpty` 抹掉（否则会在圆形图后面露出方块）。**缺图时退回文字按钮并 `print("缺失图片:", name)`** —— 比"静默返回空按钮"好，出了问题会自己说话。

## 四、美术风格决定（重要，影响今后所有美术）

用户明确：**不要平滑、要锐边、直线、低面数** —— 即 **低多边形（low-poly）** 风格。

这与项目现状一致：`GeoIcon` 占位全是多边形、世界地图是六边形、格蕾修立绘是平涂硬边、UI 全是平面样式盒。

**世界球图标的由来与教训**：助手前 7 版全走"平滑"路线（径向渐变、柔化模糊、圆润高光），**方向从根上就错了**，所以越修越"没有感觉"。中途两个具体错误也记一下：
- 低多边形 v1 的明暗用**平面方向**算 → 对一圈 12 个面等于按角度分扇区 → 成了**风车/饼图**。正解：面心归一化到单位球，`nz = sqrt(1 - nx² - ny²)` 得三维面法线（近圆心=正对镜头=亮，近外缘=侧对）。
- 面与面之间会出现**抗锯齿白缝** → 底下垫一层同色底即可。

**最终上线的是用户自己画的**：`art/ui/world-ball-s.png`（64×64，六边形蜂窝纹蓝色光球）+ `world-ball-l.png`（128×128，**目前零引用，留作备用**）。

> 待办：`art/ui/` 只有 PNG，**没有矢量源文件** —— 想改设计或导第三档尺寸就得从头来，建议补一个母版进去。

## 五、搁置项：世界系统点选逻辑（②）

**需求**：点地块 = 选中地块；点地块上的棋子图标 = 选中棋子。
**已定方案**：**保留现有"重复点同一格轮换"作为兜底** + 新增"图标直选"（好处：现有自检不用改）。

**现状**（`view_world_page.gd:323 _on_tile_selected`）：点同一格会按 `市中心 → 每个公民各一档 → 地块` 轮换；`hex_map_view.gd:_gui_input` 目前**只看坐标落在哪个六边形里，完全不分图标**。

**已发现的一个口径不一致**（改时必须处理）：
`_draw_tile` **画出该格上的所有单位（含客人）**，但轮换候选列表 **只收公民**（`if GameState.is_citizen(u)`）。所以**客人有图标但不在候选里** —— 图标直选时若点到客人，`cands.find()` 会找不到，需**退回按轮换选地块**。

**已拆好的 4 步**（每步可单独验证，随时可捡起来）：
1. `hex_map_view` 新增 `unit_icon_positions(key)` —— **把图标位置从绘制代码里抽出来**（先新增，没人用）
2. `_draw_tile` 改用它 → **绘制与命中判定共用一份几何**（否则挪了图标位置，命中会悄悄失准）
3. 加命中判定 + 一个 `unit_clicked(uid)` 信号
4. `view_world_page` 接住信号，直接选中该棋子（命中不到就退回原轮换）

> **不做的话影响什么**：不影响任何现有玩法，只是"点中某个棋子要多点几下"。用户判断 UI 还要长期改，按优先级搁置 —— **不是因为它会被 UI 变动推翻**（"点一下算什么"属于交互语义，比布局稳定）。
